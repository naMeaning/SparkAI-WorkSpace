# IIIMAGE STUDIO 持续产品硬化总 Goal

更新时间：2026-07-12

## 一、最终方向

IIIMAGE STUDIO 是一个以右侧项目 Agent 为唯一智能入口、以无限画布展示图片成果及其关系的桌面 AI 生图工作台。产品不恢复手动工作流、Agent 节点或子 Agent。用户通过自然语言、参考图和当前选中成果表达目标；Agent 自主理解任务并调用工具；画布负责呈现、整理、比较、编辑、追溯和导出结果。

本 Goal 不以“新增了多少按钮”为成功标准，而以以下闭环是否可靠为标准：

`用户意图 → Agent 上下文 → 原生工具调用 → 参数容错 → 图片执行 → 成果落盘 → 画布呈现 → 继续编辑/归组 → 导出 → 持久化恢复 → AIDebug 证据`

## 二、不可违背的工程原则

### 1. Agent 原生能力优先

- 使用清楚的主 Prompt、公开 Tool Schema、精确的当前选中上下文和可靠的工具返回值帮助模型做对决定。
- 不用关键词路由、前端伪造 tool call、首轮强制 tool choice、隐藏任务改写或无限重试替 Agent 决策。
- 模型出现理解错误，先检查上下文是否含噪、Schema 是否歧义、工具返回是否可行动；参数错误优先由工具层做无损规范化。
- 只有会改变用户意图、丢失信息或产生歧义的参数冲突才返回模型内部错误。安全等价形式应兼容，而不是制造一次额外模型往返。
- 系统兜底校验不进入用户时间线；用户只看到 Agent 的简短说明、正在调用的工具、可折叠的实际 Prompt 和独立的完成/失败结果。

### 2. AIDebug 是产品感官

- 先补观测再改复杂交互；不得用 DOM 存在、内部函数返回或历史绿色报告代替真实手势和截图。
- 每个关键场景同时验证功能、状态、手势、视觉和证据质量。
- 自动结果与截图冲突时以真实截图为准，修复产品或证据，不降低门槛。
- AIDebug 自身必须验证请求/实际窗口、DPR、画布缩放、截图来源、哈希、关键几何和性能采样的真实性。
- 每个大阶段结束后保留 GUI 供人工体验；人工反馈进入下一轮，而不是覆盖自动证据。

### 3. UI 统一而非继续叠加覆盖

- 先建立颜色、间距、字号、控件高度、圆角、边框、阴影、动效时长和层级 Token，再收敛组件。
- 设置页、节点编辑器、图片查看器、图层查看器、AI 重绘、AI 抠图、确认框和导出反馈使用同一 Header / Body / Footer 与按钮规范。
- 减少无意义边框和说明，消除空白、错位、裁切、重复状态与窄窗口下的第二套混乱布局。
- 修复本体和级联来源，不在样式表末尾无限追加覆盖；每次清理都要证明没有破坏旧版连接头、选中高亮、节点层级和最小窗口布局。

### 4. 动效服务于操作反馈

- 拖动、吸附、归组、拆组、展开、重组、选择和弹窗出现应有短促、可中断、不会拖慢输入的反馈。
- 拖动期间位置直接跟手；松手后的归位、降级或容器重排才使用短过渡。
- 支持 `prefers-reduced-motion`，在减少动态模式下保留状态差异但取消位移、发光和循环动画。
- 禁止以高成本粒子、持续滤镜、布局抖动或大面积 backdrop-filter 制造“高级感”。

### 5. 性能必须有预算

- 生产包不得携带完整 AIDebug 控制面；诊断能力应按开发/测试环境隔离或懒加载。
- 大画布不把完整成果快照无限注入每轮 system context；上下文只包含当前选中、必要关系、最近变化和受控摘要。
- 节点拖动、流式 delta、计时器和图片进度不得触发无关工作台整体重渲染。
- 图片缩略图按显示尺寸解码；离屏成果允许延迟加载；容器、查看器和画布复用受控缩略图，不重复读取大原图。
- Electron 主进程避免同步递归扫描、逐图同步哈希和高频整份 session 双写；重任务进入 Worker/批处理并提供可取消进度。
- 性能结论必须来自 AIDebug 的启动、交互、内存、长时间线和大画布场景，而不是主观感觉。

## 三、产品能力收束

### 1. 基础生成形态

- 单张：标准成果节点。
- 同一要求的多个版式：自适应多图容器，用户可比较、单独拖出、继续编辑和导出。
- 不同要求的并行批量：每张保留自己的 Prompt；默认容器化展示，最多并行 10 张。
- 连续系列：使用紧凑顺序关系，后续成果不复制首图的大卡片尺寸；每张仍是独立成果。

### 2. 电商与泛化任务不是独立工作流

以下需求由同一组图片原语组合完成，不为每个行业词新增模式按钮：

- 商品多角度：参考图 + `variants/edit` + 视角约束 + 多图比较。
- 商品文案置换：参考图 + `replace/edit` + 文字区域与保留项描述。
- 主体/商品置换：参考图 + `replace` + 新成果溯源。
- 服装上身/模特图：服装参考、人物参考与姿态/场景要求共同进入 `edit`；必须保护服装关键细节和人物一致性。
- 实物图转宣传图：主体保持、场景设计、版式与文案生成组合。
- 图片裂变：同一主体生成不同版式、图案、文案或市场语言；输出独立可挑选成果，不拼成一张大图。
- UI/直播切片：`layers` 输出真实透明 PNG 图层、重组校验、文件夹和 PSD。

每类场景都应建立少量高质量、可复现的验收样例，验证 Prompt、参考图、结果数量、主体保持、文字准确性、画布布局、继续编辑与导出闭环。

### 3. PSD 交付

- 分层 PNG 继续导出保留图层顺序、名称、显隐、透明度和画布尺寸的 PSD。
- 任意普通图片允许导出单图层 PSD；不得伪装成可编辑文字或矢量图层。
- 多图容器导出 PSD 时必须由用户明确选择“每张独立 PSD”或“同尺寸图片作为多个图层”；尺寸不一致时不能静默拉伸。
- PSD 在 Worker 中生成，写入后读回验证，失败不留下半文件；无 Adobe Photoshop 环境时如实声明只完成结构/像素交叉验证。

## 四、执行轮次

### Round 0：关闭当前阻断

- 修复六层独立 PNG 节点在中央叠放时与 `99-recomposed` 不一致的问题；不可只让右侧缩略图或文件通过。
- 修复稀疏文字透明层的屏幕采样真实性，同时保留文件 alpha 和截图合成硬门。
- 补齐跨容器真实拖拽、合并图层后的真实移动/归组、障碍节点穿线不避让、交叉线创建顺序层级、拖动前/中/后三帧证据。
- 重跑 Agent、图片集合、分层、登录、类型、构建、PSD 和独立 evidence audit。

### Round 1：AIDebug 与性能基线

- 修复 `captureState(size=null)` 请求尺寸与实际尺寸混写。
- 为启动、100/300/1000 节点、2/10 图容器、长时间线、连续流式消息、缩放/拖动和最小窗口建立性能场景。
- 记录主线程长任务、帧间隔、React 提交次数、图片解码数、内存、session 写入次数和 Agent context 字符/token 预算。
- 将完整调试控制面从生产 bundle 隔离。
- 建立 bundle 预算并扫描未引用资产；已经废弃的风格库、滤镜和工作流资源不得继续被复制进 `dist`。

### Round 2：UI Primitive 与弹窗/编辑器统一

- 建立 Token 和统一 Dialog / Drawer / Field / Button / Empty / Timeline / Viewer primitive。
- 收束设置、Prompt 编辑、FastMemory 编辑、成果编辑、独立图层编辑、AI 重绘、AI 抠图和导出反馈。
- 全局扫描空白、重复说明、未对齐按钮、滚动冲突、焦点丢失、窄屏裁切和退出后登录样式回归。

### Round 3：画布手势、层级和动效

- 统一标题拖动、图片主体拖动、容器成员拖动、Ctrl 多选、中键框选、连接头和右键编辑的命中优先级。
- 节点与线路按持久顺序分层；线路保持单段 Bézier、不避让、无箭头，交叉线层级稳定。
- 完成吸附、归组、拆组、重组和 reduced-motion 动效矩阵。

### Round 4：Agent 上下文与工具容错

- 删除外层“终端工具”策略：只有 `ask_user` 是等待态；`view_image`、`shell_command`、`experience` 和 `image_gen` 返回 `function_call_output` 后都应继续原生模型轮，由模型决定下一步和最终正文；`web_search` 由 Responses 原生执行并返回 `web_search_call`。
- 删除工具失败后的 synthetic user 修正指令和写死的图片完成话术；只保留最大轮数、额度、并发数和“同一轮同名工具 + 标准化参数哈希完全相同”的精确重复防护。
- 将全画布 system 快照改成受控的选中成果、必要关系、最近变化与摘要。
- 为成果查询增加分页/筛选；动态上下文分别设置字符与 token 预算，并保证被选中的末尾节点不会因预算被截掉。
- 审查 placeholder items、count/items、单图/多图等价参数，移除可无损恢复的额外模型往返：纯占位条目丢弃，剩一项降级标准单图，2–10 个有效项以有效项为准；存在两个合理解释时才拒绝。
- Image Gen 公开 Schema 增加容器素材 `assetIndex`，参考图增加可选 `role/purpose`，让服装、模特、商品、版式和风格参考可以被可靠区分并贯穿上下文、标准化和诊断。
- 为所有公开工具增加精确 Schema 自测、模型内部错误可行动性测试和用户时间线隐私测试。
- 验证 compact、长会话、FastMemory 隔离、新会话、新项目和清理聊天后的上下文健康。

### Round 5：图片任务闭环

- 单图、同提示词多版、不同提示词批量、连续系列。
- 商品多角度、文案置换、主体置换、实物转宣传图、服装上身和裂变样例。
- 每类均验证真实 Image 2 参数、参考图路径、数量、关系、容器布局、继续编辑、保存和重启恢复。

### Round 6：导出、持久化与大项目健康

- 普通图单图层 PSD、多图容器导出策略、分层 PSD/文件夹/合成 PNG 回归。
- 异步扫描、导入、哈希和 session 写入；崩溃恢复、临时文件隔离和多实例安全。
- 项目加载优先按已记录资产直接恢复，缺失时才后台扫描；批量导入使用流式哈希和有限并发，禁止在 Electron 主线程逐个同步读取数千张图片。
- 保存队列绑定 `projectId + revision`，切换项目和退出前显式 flush；旧项目的迟到写入不得覆盖当前项目。
- 建立项目内缩略图缓存：画布使用 thumbnail，查看器、编辑器与导出使用 original；缩略图损坏可重建且永不替换原图。
- 大项目重启后验证成果、布局组、关系、会话、FastMemory 和导出记录不串项目。

## 五、每轮交付模板

每一轮必须按以下顺序推进：

1. 写明本轮用户价值、因果链、允许变化和禁止回归。
2. 先补足观测与失败复现。
3. 修改真实数据链路和组件本体。
4. 运行专项自测、严格 TypeScript、构建和 `git diff --check`。
5. 运行相关 AIDebug GUI 套件和独立 evidence audit。
6. 人工查看关键截图；审美问题不能只看数字。
7. 更新本文件或分轮计划中的实际结果、残余风险和下一轮依据。

## 六、完成定义

只有以下条件同时满足，才可以称为可交付：

- 核心图片任务真实执行且失败边界清楚，不伪造结果。
- Agent 无关键词强制路由和外层无限修正，Schema/上下文/容错有独立证据。
- 画布手势、选择、容器、线路、分层、查看、编辑、另存和 PSD 形成闭环。
- 项目、会话、FastMemory、成果、关系和导出在重启后保持隔离与一致。
- UI 在标准和最小工作宽度下统一、无明显空白/裁切/重叠；动效流畅并支持 reduced-motion。
- 性能场景达到已声明预算，生产包不携带大段测试控制面。
- 自动化、独立证据审计和人工关键截图一致；任何真实失败不以放宽断言掩盖。

## 七、推进记录

### Production AIDebug 隔离基线

- 使用 Vite compile-time `__IIIMAGE_AIDEBUG__`：开发/测试服务保留真实调试控制面，正式构建将整段 AIDebug effect 死代码消除。
- 正式 JS 从 752,240 bytes 降至 604,025 bytes，且不再包含 `__iiimageAIDebug`、`runLayerStackSuite`、`runMixedStressSuite`、`runCanvasImageCollectionSuite`。
- 正式构建停止复制已无产品入口的 138 个风格库资源；`dist` 从约 33.39 MB 降至 864,339 bytes，仅保留 HTML、应用图标、JS 和 CSS。
- 新增 `pnpm run test:bundle`，当前预算：JS ≤ 650 KB、CSS ≤ 220 KB、完整 dist ≤ 1 MB，并验证正式图标与诊断标识泄漏。

### AIDebug 性能与窗口证据基线

- `captureEnvironment` 升级为真实性 schema：未请求窗口尺寸时明确记录 `not-requested` 和 `requestedWindow=null`；BrowserWindow bounds 不可用时保留真实错误，不再用 renderer 尺寸回填冒充。
- 新增 `pnpm run aidebug:performance`，覆盖冷启动、200 节点 hydrate/视口投影、10 图容器、pan/zoom/drag rAF、Long Task、CDP heap 和保存耗时；缺失指标记录为 unknown，不能作为绿色证据。
- 首轮基线报告：`.diagnostics/electron/aidebug-2026-07-12T22-23-00-639Z/report.json`。
- 当前数据：启动 1308 ms；200 节点 hydrate 354.3 ms、57 个视口投影；10 图容器 79.5 ms；pan p50/p95 13.9/27.9 ms；zoom 13.7/34.7 ms；drag 13.8/14.2 ms；Long Task 1 次、128 ms；JS heap 增量约 24.36 MB；保存 9.3 ms。
- 这些数字是后续优化对比基线，不代表性能已经完成；Long Task、heap 增量、200 节点 hydrate 和 zoom p95 仍是重点。
- 当前性能套件运行在明确启用 AIDebug 的开发构建中，包含观测开销；后续应拆出小型 performance bridge，并追加 production-like 基线，不能把开发态数字直接宣称为最终用户性能。
