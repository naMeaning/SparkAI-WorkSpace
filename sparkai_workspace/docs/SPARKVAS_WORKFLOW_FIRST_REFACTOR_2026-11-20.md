# Sparkvas 桌面重构方案

2026-11-20 · 产品范围已确认，进入实施前设计

首版只围绕一条完整路径展开。用户在项目画布旁创建自定义工作流，可以从一句话开始，也可以从空白开始。用户在同一个编辑器调整步骤，选择素材运行，看到成果回到画布，再将工作流保存到「我的工作流」，换项目和素材也能复用。

本方案更新 11 月 16 日规划中的首版范围、工作流入口、主题与布局方向和排期。品牌与长期扩展方向沿用原决策，电商工作流后续单独打磨。[11 月 16 日产品决策](PRODUCT_STRATEGY_SPARKVAS_2026-11-16.md)

## 1. 首版界面

- **画布**是项目的主视图，集中呈现图片、视频、已有需求节点和成果关系。保留素材、Agent 和「工作流」入口。新建项目直接进入同一画布，项目创建界面移除四种领域选择卡片。
- **工作流**打开画布旁的编辑面板。新建时可选择「描述你想做什么」或「从空白开始」。输入、步骤和输出沿执行顺序排列，选中步骤后展开参数。支持添加、删除和拖动排序，并提供键盘移动。窄窗口的面板呈现随实现验证。
- **Agent**起草或修改当前工作流草稿。用户可以阅读和编辑每一步，点击「运行」才提交工作流。结构相同的手动草稿和 AI 草稿使用同一套校验、保存和执行。
- **外观**使用实色浅色与深色主题和一个强调色。作品保持原色。借鉴 Linear 的信息层级与快捷操作，借鉴 Apple 的排版与控件一致性。用间距和细边界区分区域，常用操作位置固定，关键操作使用「新建工作流」「运行」等短文字。辅助图标提供悬停提示和无障碍名称。

| 合并 | 评审视图的图片对比 | 从选中成果后的操作菜单进入图片对比；清理专注和评审各自的页面与导航。 |

| 删除 | 素材栏和底栏重复的领域工具入口 | 电商、社媒、科研工具退出默认工具入口。旧项目仍可按需访问所用功能，后续根据需求逐项判断是否进入步骤列表。 |
| 删除 | 玻璃主题编辑器与预设切换 | 外观设置收敛到浅色与深色。旧主题迁移到相应明暗主题。 |
| 延期 | 独立 Studio 工作区、自由节点图、分支、循环、并行编排 | 首版交付顺序步骤面板。 |
| 延期 | Marketplace、Registry、第三方步骤分发、布局构建器 | 首版使用本机个人工作流库和内置图片步骤。 |
| 延期 | 电商专用流程打磨、品牌技术身份迁移 | 分别安排独立批次。旧电商模板仍通过原有兼容路径访问。 |

## 3. 工作流如何创建和运行

- **步骤范围。** 首批提供生成图片、参考图编辑、抠图和换背景。换背景作为已有图像编辑能力的步骤。输入来自本项目的受管素材、可复用参数或前面步骤的结果。缺失输入和不兼容的绑定在运行前定位到具体步骤。排序时重新校验依赖关系。
- **保存与复用。** 项目内编辑草稿。用户选择「保存到我的工作流」后，把步骤、参数默认值和输入槽位保存为本机可复用定义。其他项目打开该定义时，重新绑定本项目素材。工作流库中的定义与每次运行记录独立，修订定义后仍能查看早期运行用了哪些输入和步骤。
- **提交与结果。** 运行时冻结草稿版本、素材和参数。沿现有图片执行链派发，记录每步状态与输出资产，最终成果回到当前画布并保留来源。切换选择或折叠面板时，运行继续归属于发起时的项目。
- **失败与恢复。** 面板指出失败步骤。可重试时复用此前成功的受管产物，从失败步骤继续。遇到上游提交状态不明时，优先恢复原任务或显示待确认状态，防止重复提交和计费。恢复沿现有任务回执及日志机制。
- **编辑与执行边界。** Agent 使用当前编辑器的草稿结构和已支持步骤。用户可以接管、修改和预检草稿。实际运行复用现有任务和权限边界，断线与重启后的恢复由 Electron 主进程负责。

每次运行需要保留工作流定义版本、项目身份、输入资产、参数、步骤状态和输出资产。具体文件布局、状态枚举和 IPC 命令在实现前依据现有项目持久化和任务记录确定。公共动作变更时同步 GUI、CLI/MCP 合同和对应验证。[现有执行与持久化入口](CONTEXT_MAP.md#4-关键入口与调用链) · [旧实施计划中的模块索引](IMPLEMENTATION_PLAN_SPARKVAS_2026-11-16.md#2-当前事实与硬约束)

## 4. 旧项目与数据迁移

| 旧数据 | 迁移和验证 |
| --- | --- |
| 项目、成果、来源关系、会话、进行中的任务 | 沿现有 project/session owner 读取，使用旧项目副本核对项目身份、画布成果和任务恢复。 |
| 个人需求模板 | 输入素材槽、文字变量、操作和默认值均可保真映射时，导入为单步工作流并保留来源 ID。记录成功与需兼容的条目，重复打开保持迁移幂等。旧库作为恢复来源。 |
| 需求节点、电商模板与领域数据 | 需求节点沿原项目入口访问。专用模板与领域数据使用原类型和数据 owner，通过旧项目兼容菜单打开。 |
| ComfyUI 工作流、连接配置和凭据 | 使用原管理入口与数据 owner。接入工作流步骤属于后续事项。 |
| 玻璃预设、专注与评审视图偏好 | 玻璃主题按明暗映射到实色主题。旧视图偏好统一打开项目画布，兼容迁移项目数据和视口。 |

现有个人需求模板、电商模板和 ComfyUI 工作流分别保存。迁移按各自的数据契约处理，优先验证真实旧格式和无法完整映射的示例。[现有存储初始化](../electron-main.cjs) · [个人需求模板实现](../desktop/requirement-library.cjs) · [ComfyUI 工作流导入界面](../src/comfyui-task-fields.tsx)

## 5. 实施顺序

1. **冻结首版边界。** 同步开发约束和产品意图，区分画布上的成果关系与项目内的顺序工作流。确认步骤输入输出、运行状态、旧入口依赖和迁移样本。以现有导入、图片执行、资产注册和任务恢复为复用边界。
2. **跑通手动工作流。** 在现有画布中打开编辑面板，完成草稿、校验、顺序执行、失败恢复和结果落盘。跑通「我的工作流」，验证跨项目换素材复用。
3. **接入 Agent 与兼容入口。** 让 Agent 起草和修改同一份草稿。实现模板迁移、旧模板入口和旧项目专用功能入口。用旧项目和中途中断的任务验证兼容。
4. **收敛导航和主题。** 在替代入口可用后移除重复导航、专注和评审页面及玻璃主题编辑。统一浅深主题和共享控件，覆盖最小窗口。按桌面仓库规程完成真实 Electron 验证和后续本地打包交付。[桌面开发与验证约束](../AGENTS.md)

## 6. 验收场景

| 场景 | 通过标准 |
| --- | --- |
| 空白开始 | 添加抠图和换背景步骤，绑定一张画布图片，运行后看到有来源关系的新成果。 |
| 一句话开始 | 提示「把选中的图抠出来，再放到浅灰背景」，Agent 给出可编辑步骤。改背景参数后明确点击运行，成果回到发起项目。 |
| 换素材复用 | 保存到「我的工作流」，在第二个项目使用另一张图。第二次运行的输入和结果属于第二个项目，两份运行记录各自可查。 |
| 失败和恢复 | 模拟第二步失败与上游提交状态不明。可恢复情形复用第一步产物，状态不明情形查找原任务并可观察到无重复派发。 |
| 旧项目升级 | 清除重复入口之后，旧需求节点、旧模板、旧领域工具、独立视频和 ComfyUI 仍可从各自路径使用。重复迁移无重复项。 |
| 界面和可达性 | 实际走查 1280×800 与 884×640 的浅深主题。打开编辑面板、编排、选素材、查看失败与从成果打开对比均可操作。关键文字无裁切，键盘可完成关键动作。 |

验收优先使用本地测试素材和模拟服务覆盖成功、失败、断线和恢复。真实模型或视频请求沿用户授权边界执行。设计确认后的实现、验证和本地安装记录见 [PROGRESS.md](../PROGRESS.md)。
