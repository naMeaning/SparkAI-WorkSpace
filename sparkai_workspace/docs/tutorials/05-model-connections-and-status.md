# Tutorial 05：模型连接与运行状态（主分支开发版预览）

这篇教程适用于包含工作台优化改动的主分支开发版，不适用于当前公开的 v1.0.9 安装包。它说明如何阅读模型连接和运行证据，避免把“能读到模型目录”误解为“文生图和编辑已经验证”。

## 1. 打开模型配置

进入“设置 → 模型”，选择“配置对话模型”或“配置生图模型”。模型列表和逐模型详情分开显示：勾选框控制是否启用，点击模型名称查看该模型的连接。

需要更新服务端目录时，点击“刷新模型”。普通打开设置优先使用本地快照，不会因为打开页面就额外请求目录；刷新动作才会访问已配置的服务。

## 2. 阅读当前连接

保存过的模型会显示脱敏摘要：

- 地址来自逐模型覆盖，还是全局继承；
- 凭据来自独立 Key、模型账户 Token 或全局账户凭据；
- 实际使用的协议和同步/异步结果方式；
- 目录、文生图和编辑各自最近的状态。

完整 API Key、Cookie 和 Token 不会显示在摘要、项目文件或日志里。留空的 Base URL 或 Key 会按当前接入模式独立继承；只填写其中一个字段时，不要把它理解成整套连接都已独立覆盖。

## 3. 按证据判断能力

连接摘要可能出现下面几类状态：

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| `目录可读` | 服务返回了模型目录 | 仍需分别确认文生图或编辑 |
| `当前操作待验证` | 当前连接没有同协议、同结果方式的运行证据 | 在明确授权和费用可接受时做一次小请求 |
| `最近文生图失败` / `最近编辑失败` | 最近一次对应操作失败 | 先看脱敏错误和服务状态，不要盲目重试 |
| `最近成果保存失败` | 上游结果已返回，但本地成果保存没有完成 | 转到恢复图片结果，优先保存已有结果 |

目录可读只说明 `/v1/models` 或等价目录请求成功，不能证明图片服务、权限、参数或费用合同可用。真实验证前确认模型、素材、提示词、数量和服务商额度。

## 4. 保存与复核

修改逐模型地址、Key、账户密钥或默认模型后，先保存，再关闭并重新打开配置确认读回。切换连接会使旧连接的运行证据失效，新的摘要应重新显示“待验证”，这是为了避免把另一条连接的成功状态误归到当前模型。

如果服务返回 5xx、断连或超时，创建结果可能处于不确定状态。先保留错误摘要和任务记录，使用下一篇教程中的恢复入口；不要改一行提示词就再次派发。

## 5. 安全检查

不要在教程、截图、Issue 或日志中粘贴 API Key、Cookie、Bearer Token、签名 URL、客户图片或完整本机路径。需要提交问题时，导出脱敏诊断，并再次检查截图和文本。
