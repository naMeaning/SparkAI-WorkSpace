# Tutorial 06：安全恢复图片结果（主分支开发版预览）

这篇教程适用于包含工作台优化改动的主分支开发版，不适用于当前公开的 v1.0.9 安装包。它解决一个具体问题：请求已经发出，但应用关闭、网络中断或本地保存失败时，如何查询原任务或保存已有结果，而不重新创建一条可能重复计费的请求。

## 1. 打开恢复入口

在画布空白处打开右键菜单，选择“恢复图片结果”。恢复面板只列出当前项目的图片操作记录，不会把其他项目或其他连接的任务混进来。

面板会显示模型、请求序号、时间、已保存数量和脱敏错误类别。常见状态包括“查询原任务”“已有原结果”“保存未完成”“部分图片已保存”和“成果已保存，可恢复到画布”。

## 2. 选择正确的恢复动作

- 有原任务 ID 但还没有成果：选择“查询原任务并保存”。应用会查询原任务状态；它不会重新发送创建请求。
- 上游已经返回图片但项目保存中断：选择“恢复已有结果”。应用优先使用本地暂存的原始图片字节。
- 部分结果已经保存：先确认画布中已有成果，再继续恢复剩余记录，避免重复添加同一成果。
- 创建结果不确定且没有可安全查询的信息：先到服务商侧确认任务，不要点击生成入口重建请求。

## 3. 复核画布和来源

恢复完成后，应用会把结果写回当前项目并保留来源关系。切换项目或当前节点仍被其他任务占用时，恢复会停止并提示你回到原项目；这是为了防止把旧任务的图片写入错误的画布。

恢复完成后检查：

1. 结果数量和请求序号是否符合原任务；
2. 图片是否进入正确的项目和图片组；
3. 原图、参考图和恢复成果的来源关系是否完整；
4. 需要导出时，文件格式是否与服务返回的实际格式一致。

## 4. 失败时怎么处理

点击“刷新记录”重新读取状态。若本地保存再次失败，保留记录并稍后重试恢复；不要用新的提示词覆盖原任务。明确的配置错误需要回到模型连接设置修正，原任务仍按原连接查询，不能用新连接冒充旧凭据恢复。

恢复功能只处理原任务或已经收到的原结果，不承诺上游一定支持取消，也不会把一次失败伪装成成功。真实服务是否支持对应的任务查询和计费规则，以你配置的服务商为准。
