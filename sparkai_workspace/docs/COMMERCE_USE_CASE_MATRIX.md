# 电商与泛化图片任务矩阵

更新时间：2026-07-12

## 目的

把电商高频请求映射到同一套 Agent、Image Gen、参考图、成果关系和画布展示能力，避免为每个行业词新增按钮、工具或手动工作流。当前环境没有可连接的浏览器实例，因此本文件先记录已由用户明确提出并能从产品原语推导的场景；公开市场资料核对需在浏览器可用后补证据，不在此冒充已完成外部调研。

## 统一输入语义

- `source`：当前选中、需要保留主要结构的成果。
- `reference`：为模型提供服装、商品、人物、风格、版式或文案依据的项目库图片。
- `assetIndex`：当 source 是多图容器时，精确指定其中一张图片。
- `role/purpose`：可选参考图角色，例如 `model`、`garment`、`product`、`layout`、`style`、`logo`。
- `parentId`：新成果的主要来源节点，用于溯源，不表示执行顺序。

## 场景矩阵

| 用户目标 | Image Gen 表达 | 参考图角色 | 画布结果 | 必须验证 |
| --- | --- | --- | --- | --- |
| 生成单张商品图 | `generate/edit + count=1` | 可选 `product/style` | 标准单图节点 | 数量 1、Prompt 可见、可继续编辑/另存/PSD |
| 同一商品多个版式 | `variants + count=2..10` | `product/layout/style` | 自适应多图容器 | 不拼成九宫格大图；每张独立 Prompt/资产；可拖出 |
| 批量不同商品或文案 | `generate/variants + items + parallel` | 每项明确 source/reference | 自适应多图容器 | 最多并行 10；失败项独立；成功项不回滚 |
| 连续系列海报 | 多轮 `generate/edit + parentId` | 当前成果 + 系列风格 | 紧凑连续关系 | 后续节点紧凑；风格一致；每张独立可用 |
| 商品多角度 | `variants + 每角度 item` | `product` | 多图容器 | 正面/侧面/背面/细节各自独立；主体一致；角度不重复 |
| 商品文案置换 | `replace/edit + parentId + assetIndex` | `layout/logo` | 新的衍生成果 | 商品、背景、版式保持；目标文字准确；原图不覆盖 |
| 商品主体置换 | `replace/edit` | `product` + 可选 `layout` | 新的衍生成果 | 背景、阴影、透视和文案保持；新主体比例合理 |
| 服装上身/模特图 | `edit/replace` | `model` + `garment` | 新的衍生成果 | 服装版型/图案/颜色保留；人物与姿态合理；来源明确 |
| 实物图转宣传图 | `edit` | `product` + `style/layout` | 单图或多版容器 | 主体不漂移；场景、灯光、留白和文案区域可用 |
| 同款不同图案/SKU 裂变 | `variants/items` | `product` + 各图案 | 多图容器 | 仅指定区域变化；其余结构保持；每个 SKU 独立资产 |
| 中文宣传图改外语 | `replace/edit` | `source` + 可选文案表 | 新的衍生成果 | 字符准确、无乱码、版式不溢出、商品不改变 |
| UI/直播切片 | `layers` | `source/layout` | 多个独立透明 PNG 节点叠放 | N 层=N 节点、非背景真实 alpha、重组一致、PSD/文件夹 |

商品多角度的验收不能只检查“生成了 N 张”。每个 `items.prompt` 必须写明独立方位角、俯仰角、可见侧面或顶部结构及投影变化；缩略图层面仍无法一眼区分时，应视为质量不足，而不是用文件数量宣称完成。

## 统一失败边界

- 模型无法可靠保持文字时，工具应返回真实结果和限制，不能伪造“文字已准确替换”。
- source/assetIndex/参考图角色存在歧义时，应由 Agent 简短询问或明确内部参数错误，不猜路径或图片。
- 多版结果必须是多张独立图片；拼贴预览不能代替独立资产。
- 服装上身和主体置换不得覆盖原图；所有结果建立新资产与来源关系。
- 分层任务任一指定图层失败、尺寸不一致、alpha 不可靠或重组不完整时，整组不能宣称完成。

## 场景级验收模板

每个场景最少保存以下证据：

1. 用户原句、选中节点、多选节点、参考图数量与角色。
2. 模型原生 tool call 及标准化后的唯一参数；不得有关键词强制路由。
3. 工具请求数量、并发峰值、成功/失败项、实际图片模型。
4. 生成文件、尺寸、哈希、alpha/文字/主体保持等适用检查。
5. 节点、容器、关系、选中状态和 Prompt 展示。
6. 拖出、继续编辑、另存、PSD 与重启恢复。
7. 关键 GUI 截图和独立 AIDebug evidence audit。

## 第一批真实样例

后续真实 Image 2 验证优先使用六组可复用样例：

- 运动鞋：白底主图的 4 个版式与 4 个角度。
- 咖啡杯：保留商品，替换中文/英文卖点和背景场景。
- 服装平铺 + 成年模特：上身图与 3 种姿态。
- 香水瓶：主体置换但保留原背景、阴影、构图和文字。
- 同款 T 恤：6 种图案/SKU 裂变。
- 东方审美技术主题海报：单图、系列、多版和六层 PNG/PSD。

测试成果统一放在项目内明确的诊断/样例目录，不混入用户原图，不暴露服务端 Key 或上游地址。
