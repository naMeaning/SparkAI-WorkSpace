## 1. 任务契约与使用方式

用户要求根据当前项目，从性能、画布左/右键操作、画面大小和配置体验、New API / Sub2API / 生图接口有效性提出详细设计，再交给执行模型实施。

本方案将工作分成六个包：接口状态可信、画布操作一致、失败可恢复、小窗口好用、配置可理解、大项目性能稳定。先修正可能误导用户或操作对象的问题，再优化空间和速度。

本轮的文档编写不授权产品实现或真实模型请求。用户后续发送本文第 12 节的执行 Prompt 后，执行模型应把相应范围登记到当前 Goal，再按阶段实施；无需为了文档已经明确的常规实现选择重复询问。新的付费请求、外部生产变更和正式发布仍按仓库规则处理。

### 1.1 保持的产品边界

- 同一项目、画布、资产、Session、TaskScope 和项目 Agent；四领域仍为同一底座的能力投影。
- 右侧 Agent 是唯一控制中心；沿用 image_gen 和现有统一图片服务。
- 画布关系表示来源，不因连线、拖动、菜单展开或配置变更自动执行任务。
- 保留单击图片查看、双击编辑及多选保护；手势冲突按第 5 节统一。
- 模型 ID、供应商、渠道、Adapter、Base URL、凭据分别建模，保留上游完整模型目录。

- GUI、共享命令、CLI/MCP 共用业务 owner；不创建平行的选择、连接、任务或项目系统。

## 4. 工作包 A：接口、渠道与模型可用性

### 4.1 当前接口边界

| 对象 | 当前代码/资料依据 | 未证明的范围 |
| --- | --- | --- |
| OpenAI-compatible Images | 生成 JSON、编辑 multipart 适配与本地测试 | 任意 New API 部署/Token/模型均支持 |
| xAI Images | 生成与编辑 JSON，内联结果优先 | 当前中转站与原生合同完全一致 |
| Gemini native | generateContent / inlineData 适配 | 任意渠道均暴露该原生路径 |
| Sub2API | 本地上游快照存在 /v1/images/generations/async、/v1/images/edits/async、/v1/images/tasks/:task_id | 当前线上版本、路由、模型权限与密钥可用性 |
| SparkAI Extension | 可选 /v1/image-tasks 包装，独立服务 | 任意渠道支持此自定义合同；编辑/上传支持不能由文生图包装推断 |
| Grok 当前连接 | 最新已授权单张请求为 502 | 渠道恢复、是否已消费、重发一定安全 |
| Seedance | 独立 create/poll/download 链路已开发 | 真实协议及计费范围已验证 |

### 4.2 精确绑定证据

复用现有 modelAccessProfiles。Main 为每次请求冻结有效连接身份，再将结果回写到这次请求使用的身份，不读取请求完成时可能已经改变的当前设置。

证据至少限定：

~~~text
connection identity + credential revision
+ original model ID + protocol + transport profile
+ operation + tested parameter scope
+ observation stage + observedAt
~~~

- 连接身份基于实际归一化地址和现有凭据引用/内部指纹；原始 Key 不进入公开 DTO。
- 同一账户 Token 换 Key、逐模型覆盖、地址路径、Adapter 或传输改变，都不能继续继承新配置未验证的成功。
- 保留模型原始 ID 和大小写用于发送；内部匹配遵循现有规范，不修改上游模型名称。
- 文生图、参考图编辑、蒙版、多参考图、透明背景和指定分辨率分别记录覆盖范围。
- HTTP 返回有效图片与最终受管资产/项目保存成功分开记录。
- 保留最近成功、最近失败和失败阶段，后一次失败不能被旧成功徽标掩盖。
- 旧 runtime-verified 若缺少可证明的连接身份，迁移为“历史记录，当前连接待验证”，不得按猜测重新认证所有连接。

建议扩展现有状态结构和迁移，不引入第二个连接管理器。确有新字段时，Main、public DTO、Renderer、缓存归一化与上下文地图同批更新。

### 4.3 用户可见状态

| 状态文案 | 证据 |
| --- | --- |
| 配置完整 | 本地校验 |
| 模型目录可读取 | 当前连接的目录 GET 成功 |
| 上游声明支持编辑 | 上游元数据 |
| 文生图曾成功 | 同身份、同模型、同操作的有效响应 |
| 成果保存成功 | 下载/解码/受管落盘/项目记录完成 |
| 最近请求失败 | 最近失败时间、操作、脱敏原因 |
| 当前配置待验证 | 配置改变或证据不足 |

这些是不同维度，不是必须依次完成的向导。常规界面显示简短摘要，例如“目录可读 · 文生图曾成功 · 编辑待验证”，详情再展示证据时间和范围。

普通打开设置读取已有缓存。目录刷新与真实生成验证分开；目录可读不代表模型可消费，真实生成一次也不代表所有参数组合可用。

### 4.4 协议与传输

优先级：用户显式配置 > 同身份下已确认的协议画像 > 上游声明且客户端支持的合同 > 标注低置信度的兼容推断。

- New API / Sub2API 标签用于配置模板，不能单凭域名或路径字符串决定任务协议。
- async 必须解析到具体的创建/轮询合同，不能向任意端点追加 /async。
- OpenAI Images + 同步、支持的 Sub2API Images + 异步分别验证。
- xAI/Gemini 与异步任务的组合，只有明确合同和适配支持才能开放；不能从模型名或同名渠道推断支持。
- Extension 的任务端点单独标识，继续作为可选服务，不成为普通生图必需项。
- 不用连续发送收费 POST 的方式试探协议，不在未知创建结果后换协议重发。
- 旧连接保留原有效行为；迁移记录配置来源，避免自动切换请求出口。无法确定的迁移项显示待确认/待验证，不伪造证据。

### 4.5 验收

1. A 成功不会影响 B，B 不会被补入未经验证的模型。
2. 在途请求期间切换连接，结果只归属原冻结身份。
3. 换 Key、URL、协议或传输后，旧成功保留为历史但不认证新配置。
4. 目录 GET 成功不会认证生成、编辑、视频。
5. 请求成功而下载/解码/保存失败，只记录对应阶段。
6. URL 归一化覆盖含 /v1、路径前缀、尾斜杠；凭据不能跨连接错误继承。
7. Adapter 验证 method、path、JSON/multipart、认证头、模型 ID、轮询响应及空结果。
8. 不支持的参数/协议组合派发前拒绝，已有合法配置可迁移并重启读回。
9. 不泄漏凭据、原始上游敏感正文、签名 URL；模型目录保持完整。

## 5. 工作包 B：画布鼠标与选择契约

### 5.1 推荐交互表

| 操作 | 目标行为 |
| --- | --- |
| 左键点击标题或边框 | 单选；已有多选时保留已接受的多选保护 |
| 左键点击图片内容 | 查看大图；查看行为本身不改变已冻结任务范围 |
| 双击图片/标题 | 打开成果编辑器 |
| Ctrl/Meta + 单击 | 增加或移除选择 |
| 左键点击空白 | 收起菜单，保留选择 |
| 选择工具下左键拖空白 | 框选，空框保留原选择 |
| 平移工具下左键拖空白 | 平移 |
| 中键拖动 | 平移 |
| Space + 左键拖动 | 临时平移，松开恢复原工具；不因当前工具是平移而反向变成框选 |
| 拖标题/边框 | 只移动节点 |
| 拖图片到另一图片/容器 | 显示接收预览，松手后按已有资产/布局规则归组 |
| Escape / pointercancel / 失焦 | 取消当前手势，回滚临时状态 |
| 明确“取消选择”操作 | 清空选择 |

中键平移/左键框选是本方案要明确固化的行为，实施时同步旧产品文字、导航提示和测试。不得只改提示而让代码保留另一套规则。

多选保护下，“当前主项”和“选中集合”继续来自现有 selection reducer。浏览集合之外的图片不应偷偷替换 Agent 的选择集合；需要只选该图时提供明确的“只选此项”操作，复用现有 replace 动作。

### 5.2 菜单作用域

| 命中目标 | 菜单对象 |
| --- | --- |
| 空白画布 | 创建、导入、导航；已有选择可在独立分组中提供集合动作 |
| 已选集合中的节点 | 已选 N 项 |
| 未选中的节点 B | B 的单项菜单，清楚显示对象名称 |
| 容器内图片 | 具体图片槽位 |
| 容器标题 | 整个容器 |
| 关系线 | 该条真实关系 |

菜单打开时冻结 targetKind、targetIds、assetSlot、worldPosition 和相关项目 revision。它只表达这次菜单目标，不构成第二份选择状态。

右键 B 时允许保留原多选，但删除、导出、编辑等动作必须携带 B 的显式目标；不得再次读取全局 selection 而操作 A。如果动作进入 Agent/需求执行链，来源必须由菜单目标解析后显式传入，并在界面说明作用对象。

动作执行前校验对象仍存在、资产槽位身份和节点锁；过期目标应拒绝或刷新，不能套用到新对象。具体关系菜单保持真实 edge 身份，不能把“删除这条线”变成“断开全部”。

### 5.3 手势状态与性能

- 使用一个明确的手势状态：idle、pending、pan、marquee、node-drag、asset-drag、resize、connect。可沿用现有 refs，不为此引入大型状态库。
- 首次移动约 4–6 CSS 像素后进入拖动；阈值与 DPI、缩放关系需在真实指针测试中固定。
- 临时 transform / 归组预览与最终 mutation 分离；一次拖动提交一个逻辑操作，取消不提交。
- 单击计时器在双击、拖动、右键、取消、卸载、切换项目时清理；慢双击和系统输入节奏列入验收。
- 框选依据世界坐标节点边界，不仅遍历已挂载 DOM。图像容器的宿主/成员映射沿用 canonical layout projection。
- 高频手势预览按 requestAnimationFrame 合并；避免每个 pointermove 全量 React 更新或遍历测量 DOM。
- 中键与临时平移可覆盖作品表面；输入框、按钮、菜单、连接头等交互目标需有明确优先级，不能抢占文本编辑。
- 菜单坐标按实测尺寸夹紧视口，不能只依赖估计高度。

### 5.4 滚轮与触控板

保留鼠标滚轮围绕光标缩放的习惯，统一处理 deltaMode、连续滚动幅度、上下限与滚动锚点。触控板双指平移/捏合缩放提供明确输入策略；不能仅凭单次 delta 数值自动猜设备并切换规则。

工具菜单、设置表单和查看器拥有自身滚动区域，滚轮不能穿透改变画布。输入模式如果需要用户配置，保持少量选项并持久化到现有设置 owner，不引入第二套 viewport。

### 5.5 验收

真实 Electron 指针路径覆盖轻点、慢双击、拖动后松手、Ctrl 多选、空白右键、未选对象右键、容器槽位、线菜单、窗口失焦和 pointercancel。

同时检查：可见高亮、selection reducer、Agent SOURCE、实际命令目标、撤销结果、项目保存/重载后的资产和关系。在不同画布缩放与 100%/125%/150% DPI 下重复关键边界；不能只用 DOM 存在断言。

## 6. 工作包 C：失败分类与恢复

### 6.1 Main 拥有操作记录

沿用现有统一图片服务、项目保存与任务控制，在 Main 维护轻量图片操作记录。先补齐 service → transport 的 onAccepted / onStatus 等事件传递，再决定最小持久化实现。已有视频任务恢复可参考，但不得混用视频与图片的 provider 合同。

~~~mermaid
flowchart LR
    A[本地预检] --> B[提交请求]
    B --> C[已受理或等待结果]
    C --> D[收到图片结果]
    D --> E[下载与解码]
    E --> F[受管资产与项目记录保存]
    B --> U[结果不确定]
    C --> U
    D --> R[结果获取或处理待恢复]
    E --> R
~~~

建议记录：schemaVersion、projectId、operationId、requestIndex、来源资产身份、冻结参数摘要、连接身份、上游 taskId、阶段、时间、脱敏错误类别、最终受管资产 ID。具体存储位置和迁移需通过当前项目持久化 owner，记录到上下文地图。

不持久化 Key、Cookie、签名 URL、输入图片的大段 Base64 或重复图片副本。恢复时按原连接凭据引用解析；凭据已改变或失效时明确提示，不用新连接查询旧任务。

提交前写入操作身份；取得 taskId 后尽快保存。结果发布与项目 revision 协调，operationId + requestIndex 保持幂等，重复事件不得生成第二组节点。应用崩溃后，已保存资产可与操作记录对账；不能因最后一次 UI 确认丢失重新派发。

### 6.2 状态到动作

| 状态 | 允许的下一步 |
| --- | --- |
| 本地校验失败、尚未派发 | 修改配置后执行 |
| 上游明确拒绝且确定未受理 | 展示原因，修正后由用户重新执行 |
| 已有 taskId | 查询原任务；查询失败可按合同退避重试 |
| 已收到图片结果、下载失败 | 获取原结果，不重新生图 |
| 本地处理/保存失败 | 重试本地处理/保存 |
| 创建结果不确定 | 查看脱敏诊断、到渠道核对，不自动重发 |
| 多图部分成功 | 保留成功项，分别展示失败和不确定槽位 |

- 普通“失败”不能自动等同于“安全重试”；先判断是否派发、是否受理、是否收到结果。
- 同步接口若没有可查询 taskId，重启后可能只能恢复“不确定”，不得承诺取回不存在的恢复句柄。
- 签名 URL 只在内存短期使用；重启后优先通过原 taskId 重查，无法重取时明确说明限制。
- 幂等键不意味着上游一定实现幂等；创建结果未知后不靠重发试探。
- 取消本地等待与上游取消成功分开；已受理请求的占用与实际 Promise 收尾遵守现有准入控制。
- Extension 服务重启后未完成任务标记失败、不自动重放的现有合同继续保持。
- 动态过程仍由 Agent 时间线显示；画布保留结果与静态占位，避免重复滚动进度。

### 6.3 验收

本地 HTTP 模拟覆盖 4xx、429、502、创建连接中断、缺 taskId、轮询暂时错误、结果下载失败、损坏图片、写盘失败、项目保存失败、取消与重启。

每个场景记录图片 POST 次数、poll 次数、operation/slot、资产数量与项目重载结果。已有成功项不得丢失，不确定创建不得自动重发；重复完成事件只能交付一次。恢复能力需真实重启验证，不能仅测纯函数状态。

## 7. 工作包 D：布局与工具入口

### 7.1 空间分配

保留当前已完成的模型列表/详情分栏、启用/默认独立按钮和 DialogShell 八向 resize。以下尺寸是设计基准，须用实际布局验证：

| 区域 | 建议 |
| --- | --- |
| 素材轨 | 约 56–64 CSS px，扩展内容按需展开 |
| Agent 侧栏 | 默认约 360–400 px，继续可调 |
| 最小支持窗口的画布 | 优先保留约 460–480 px 可用宽度 |
| 正文 | 约 14 px，辅助信息不低于 12 px |
| 主要按钮 | 约 36 px 高，图标按钮保持明确命中区 |
| 弹窗 | 标题/底部动作固定，正文一个主滚动区域 |

Agent 最大宽度按“可用工作区 − 素材轨 − 画布最低工作宽度 − 间距”计算，并与既有最小值/上限共同夹紧。用户偏好宽度与当前窗口允许宽度分离；缩窗临时夹紧，放大恢复偏好。

在极限尺寸下保持操作可达，必要时由用户进入已有专注模式。折叠、停靠和独立 Agent 窗口始终投影同一个运行状态，不卸载或复制 Runtime。

### 7.2 工具导航

- 常驻 3–5 个高频入口，按实际空间减少。
- 一个“全部工具”菜单，提供搜索、领域分组和最近使用。
- 未常驻的工具进入菜单，避免逐页查找。
- 复用现有 command registry、插件启停、领域投影和快捷键。
- 尊重用户隐藏/固定偏好，不能把工具可见性变成权限或能力开关。
- 新快捷键先检查注册表冲突；工具搜索仅查找现有命令，不成为另一套执行入口。

常用动作一次点击可达；其余动作通过打开菜单和搜索可达。菜单与键盘焦点行为复用共享 MenuSurface。

### 7.3 视觉与验收

继续使用现有 Glass token 和明暗主题。文字、菜单、表单优先保证对比度；图片和视频内容保持原色、无模糊滤镜。拖动期间沿用低成本渲染策略。

在 884×640、1280×820、1920×1080 与 100%/125%/150% DPI 下检查：画布实际宽度、Agent 输入可用性、长标题、菜单首尾、键盘焦点、弹窗正文和底部动作、独立 Agent 同步。使用截图和矩形/命中断言，不只检查文字。

## 8. 工作包 E：参数与连接配置

### 8.1 三种“大小”

| 概念 | 影响 | 入口 |
| --- | --- | --- |

### 8.2 日常图片配置

沿用现有集中弹窗，展示实际默认模型、比例、分辨率、数量、质量、请求尺寸、作用范围和保存状态。

- 现有比例/分辨率能力约束继续使用同一 owner，补充质量等字段的一致性。
- 切换模型造成参数不兼容时明确说明调整，不静默发送被改写的值。
- 多模型池按实际派发模型再次校验，不能仅用默认模型的能力校验所有候选。
- “启用多个模型”不意味着每次自动向所有模型派发。
- 提交时冻结最终有效参数；运行中/运行后配置变更只作用于后续请求，遵循当前运行锁规则。
- 图片模型的既有默认/优先政策保持；面板摘要必须来自最终解析结果，不能只复制表单值。
- 成果详情区分请求参数、上游响应、文件实测与本地处理。请求 4K 而返回较小图时，不能用本地放大冒充原生 4K。
- 原格式与原始字节保存遵守现有产品合同；本地另存为转换仍是独立链路。

### 8.3 实际连接摘要与保存

在现有模型详情中显示紧凑摘要：

~~~text
地址来源：逐模型覆盖 / 全局继承
凭据来源：独立 Key / 模型账户 Token / 全局账户 Token
协议：实际 Adapter
结果方式：同步 / 已配置的任务合同
验证：目录、生成、编辑各自最近证据
~~~

由 Main 的真实解析器生成脱敏摘要。Base URL 和 Key 仍分别继承，不将一个字段的覆盖误描述为整套连接完全独立。

图片偏好保持自动保存，并显示保存中、已保存、失败；连接地址/凭据沿用草稿、保存、取消。关闭弹窗不得吞掉在途保存失败。普通打开设置离线优先，显式刷新才执行相应目录请求，不额外触发模型调用。

可提供明确标注的一次真实生成验证入口，测试参数、数量和费用性质在该动作前可见；正常创作仍直接执行用户已发出的任务，不新增普遍费用确认流程。

覆盖默认模型与运行时最终模型一致性、参数不支持提示、多模型池、独立字段继承、保存/取消、快速连续修改、保存失败、关闭重开、重启读回、切换连接导致证据失效。主/独立 Agent 与手动生图、CLI 使用同一有效参数合同。

### 9.1 先测量

### 9.2 候选瓶颈与最小设计

| 候选 | 需要测量 | 有证据后的优先方案 |
| --- | --- | --- |
| 可见集合扩展关联节点 | 高连接度节点带入的屏外挂载数 | 关系线使用现有节点几何，减少为绘线挂载完整节点 |
| 所有选中项保持挂载 | 大范围多选后的 DOM/解码量 | 选择逻辑与可见组件挂载分离 |
| 框选逐事件状态/DOM 测量 | React commit、layout、long task | 世界坐标边界 + rAF 合并 |
| 视口提交延迟 | 大幅平移的新区域空白时长 | 交互期间限频更新可见集合，保留临时 transform |
| 长对话展开 | 大量历史和流式输出下的 commit/heap | 先优化分页与稳定组件，必要时才窗口化 |
| 缩略图/解码 | 队列、重复请求、缓存、原图并发 | 复用 256/512/1024 桶和 Worker，按测量调整调度 |
| 保存与关系计算 | 拖动时持久化次数和计算耗时 | 完成后单次逻辑提交，保留 revision 队列与退出 flush |
| 大型编排文件 | 改动传播和 owner 混杂 | 只抽取本轮触及的纯策略/计算，不先全量重构 |

不引入全新画布引擎或状态库，不为了 Bundle advisory 数字机械拆文件。图片画质、来源关系、选择、撤销与保存是优化的不变量。

### 9.3 指标

| 指标 | 当前基线门禁/目标 | 说明 |
| --- | --- | --- |
| 标准夹具工作区就绪 | 现有 ≤3500ms | 保持定义，不混淆登录网络耗时 |
| Renderer boot | 现有 ≤2600ms | 与工作区就绪分别记录 |
| 缩放/平移/拖动响应 P95 | 现有 ≤34ms | 同环境比较 |
| JS Heap | 现有标准夹具 ≤160MiB | 不代表进程总内存或所有 4K 场景 |
| 挂载节点 | 现有标准夹具 ≤80 | 需保留测量语义，不隐藏真实可见内容 |
| 视觉帧间隔 | 现有 P95≤150ms、中位≤34ms、慢帧率≤15% | 当前门禁通过不能直接等同流畅 |
| 常用场景视觉体验 | 建议 P95≤33.4ms | 新设计目标；先测基线，再固定代表场景和门槛 |
| 操作阶段 long task | 保持现有最大≤120ms | 不以平均值掩盖长卡顿 |
| 内存稳定性 | 多次切项目/查看器/缩放后趋于平台 | 同时报 JS Heap 与进程内存，不能仅一次采样 |

新增目标不能标成当前已达成。保留每轮原始数据和失败项；如果基线已失败，记录失败并区分本轮引入的回归，不能修改阈值制造通过。
