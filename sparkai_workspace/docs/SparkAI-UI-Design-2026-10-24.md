## 1. 本轮决策

先做好日间、夜间两个普通主题，并统一按钮和配置的层级。使用中性色、实色表面、适量留白和单一主操作，让图片成果与对话内容占据视觉中心。

借鉴用户所说的 Codex 的朴素方向，不声称复制其官方设计规格。保留 SparkAI 的单画布、右侧唯一项目 Agent、成果关系和原有执行能力。

建议实施范围：主题、共享控件、工作区入口、Agent 面板、图片参数与现有设置的信息收纳。上一轮的独立设置 BrowserWindow、跨窗口 revision 保存、自定义站点登录、更新协议、ComfyUI 平台改造保留为后续范围，不作为本轮 UI 交付的前置任务。

用户将交接 prompt 发给执行模型后，执行者应在接受实施时同步 GOAL/PROGRESS。原设计交付未改写现有仓库的未提交文档；后续归档仅补文档位置与导航，保留已有开发记录。

## 3. 日间与夜间的视觉规范

两个主题共用布局、字号、圆角、交互与信息层级，只切换语义色。

| 语义用途 | 日间 | 夜间 |
| --- | --- | --- |
| 画布/应用背景 | #F6F6F6 | #181818 |
| 导航、Agent、普通面板 | #FFFFFF | #202020 |
| 菜单、弹窗浮层 | #FFFFFF | #282828 |
| 悬停底色 | #F0F0F0 | #303030 |
| 选中底色 | #E8E8E8 | #343434 |
| 正文 | #242424 | #ECECEC |
| 辅助文字 | #666666 | #B0B0B0 |
| 普通分隔线 | #E3E3E3 | #383838 |
| 必要输入/选中边界 | #858585 | #999999 |
| 主按钮底色/文字 | #242424 / #FFFFFF | #ECECEC / #202020 |
| 键盘焦点 | #5D5D5D | #B7B7B7 |

这些值是实施基准，需在实际背景上计算对比度。正文与必要辅助文字 ≥4.5:1；焦点、选中标志、必要控件边界 ≥3:1。普通装饰分隔线不承担控件识别。

- 普通主题不显示玻璃模糊、背景图片、噪点、渐变描边、发光；浮层不透明。仅菜单和浮窗允许轻阴影。
- 彩色用于真实错误、警告、成功和已有成果关系，同时提供文字/图标。作品保持原色，不对图片、视频、透明内容加暗化或单色滤镜。
- 字体沿用 Windows/中文回退。表单正文 14px，对话正文 15px，辅助说明 12px；不能靠缩小字号解决拥挤。正文行高约 1.5–1.6。
- 间距采用 4/8/12/16/24px；控件常规高 32–36px；图标 16px；图标操作命中区至少 32px，触控约 44px。
- 控件圆角 6px，输入容器 8–10px，弹窗 10px。避免每一行都做成胶囊或阴影卡片。
- 每个独立任务区域最多一个实心主按钮；常用次操作用轻边框/文字，低频操作进入该区域的菜单。

### 默认值和兼容

建议新装默认日间 light-classic，外观页首先只露出日间、夜间两张选择卡。保留持久化 ID，对用户显示“日间 / 夜间”。

明确保存过主题的旧用户保持原选择；无新字段的旧配置继续既有兼容迁移，不能把旧 theme 字段等同于新装。其他玻璃/自定义主题置于“更多外观”，仍可访问，原参数与背景偏好保留。切回旧主题恢复原参数。

旧用户当前使用其他主题时，首屏显示“当前：主题名称”和进入更多外观的入口，避免两个基础卡都未选中却无法理解当前状态。

本批不引入新的主题体系、日夜定时器或第三套“跟随系统”状态。未来增加跟随系统时，它只负责选择两个基础主题，并需固定 Main/启动/独立窗的同步合同。

## 4. 工作区如何变简洁

维持窄素材轨、成果画布、右侧 Agent，不新增导航大侧栏。桌面最小窗口仍为 884×640；保持已有布局 owner 的 64px 素材轨、至少 464px 画布预留、Agent 320–720px 夹紧规则。概念稿为聊天内窄预览提供的纵向重排不得搬进桌面产品。

| 区域 | 默认露出 | 收纳位置与规则 |
| --- | --- | --- |
| 顶栏 | 项目名下拉、当前创作领域、搜索、账户及系统窗口操作 | 新建/重命名/移除/项目导入导出进项目菜单；帮助/关于进相应全局菜单；主题统一从设置访问 |
| 素材轨 | 添加、成果、图层、需求、模板；底部设置 | 历史会话统一由 Agent 标题下拉进入；不复刻一排领域工具快捷按钮 |
| 画布视图 | 一处“画布/专注/评审”选择 | 保留现有视图 ID 和选择语义，不同时占用三个大按钮 |
| 画布底部 | 选择/平移、缩放、适配；一个“工具”入口 | 复用现有搜索、领域分组、最近使用；最近三项在菜单内，不默认铺开五个插件按钮 |
| 单图选中 | 编辑、导出、更多 | 点击图片仍可查看；参考用途、关系、删除等进图片菜单；多选继续投影原有命令 |
| Agent 标题 | 会话名下拉、新建、更多、折叠 | 记忆、清理、停靠/浮动/独立窗进更多；历史在会话名下拉 |
| Agent 内容 | 用户要求、答复、结果、当前任务状态 | 已完成工具步骤合并为可展开行；进行中、失败、待回答问题不得默认收起 |
| 输入区 | 素材、图片设置、发送；选中时一行上下文 | 不重复显示顶部当前选中；直接生图降为明确文字操作，与 Agent 发送分开 |

移入菜单只改变发现路径，不停用能力。菜单有中文标签、键盘入口、Esc 返回和焦点恢复，不能仅在鼠标悬停时出现。当前领域文字在最小窗口仍保留。

### Agent 关键状态

- 空闲无选中：不显示空的当前选中条，不把画布本身当素材。
- 选中一张：显示标题与角色；多选显示数量，可展开管理原图/参考图与序号。不制造第二份 selection state。
- 提交：实心发送调用原 Agent 链路，Ctrl+Enter 一直是发送给 Agent；普通 Enter 保持原换行/命令规则，中文输入法组合事件不发送。
- 直接生图：保留独立文字动作、明确名称与原可用条件，不按关键词把发送切成生图，不重新引入普通/Goal 模式切换。
- 运行：一条状态行显示阶段；停止始终可见，暂停/恢复随状态出现，补充要求沿用现有 steer。Main 确认前保持正在结束，不提前伪装空闲。
- 完成：收起正常工具明细，显示可定位成果；错误和部分成功保留，不用绿色完成掩盖。

## 5. 配置只在需要时展开

沿用上一轮五分类方向，本批先落在现有设置宿主，不实施独立 BrowserWindow/revision 合同。

| 分类 | 第一层 | 深一层 |
| --- | --- | --- |
| 连接 | Agent 对话、图片服务的当前摘要与配置入口 | 账号/自定义接入、模型目录、逐模型覆盖、代理、既有 ComfyUI/本地 Agent 管理、视频连接 |
| 生成 | 图片模型摘要、比例、清晰度、数量 | 质量、种子和实际支持的参数；Agent 推理/上下文/Prompt 用单独编辑入口；既有视频默认配置 |
| 外观 | 日间、夜间 | 更多主题、玻璃、已有背景/布局偏好；不新增一排滑块 |
| 扩展 | 已启用扩展、快捷键/工具显示 | 现有 Agent 集成与插件高级配置 |
| 更新 | 当前版本、检查结果、现有更新动作 | 发行信息/诊断详情；不改变协议或添加不存在的自动更新能力 |

旧 section 映射：access→连接；models→连接/模型目录；agent→生成/Agent，本地 provider 深链接到连接；tools/plugins→扩展；appearance→外观；updates→更新。保留原入口的具体深链接目标。

图片配置首屏只摆模型摘要、比例、清晰度、数量。完整目录通过“管理模型”打开；默认模型与已启用池继续独立，不静默删除服务端模型。质量/steps/cfg/sampler/scheduler/seed 放入高级，只显示当前服务支持字段；已有非默认值显示“高级参数已自定义”。无效参数错误不得藏在折叠区。

全局设置沿用现有草稿、保存/取消和脏草稿关闭保护，底部一组保存操作。图片配置仍遵循当前即时保存合同，显示保存中/失败及重试，不能因为视觉统一混淆两种语义。打开普通设置不新增模型请求、目录刷新或远端能力探测；网络动作仍显式触发。

## 7. 验收标准

1. 同一项目、同一画布位置、同一组本地图片采集日夜对照，覆盖空白、单选、多选和运行/失败；不用新真实模型请求凑证据。
2. 1280×800、884×640 下顶栏/工具/选中浮条/输入框/保存按钮不遮挡；125%/150% DPI 的真实设备情况分别记录，CSS viewport 模拟不能称为真实 DPI 通过。
3. 启动期、React 第一帧、磁盘加载后主题一致；切换不重挂画布，不改变节点 DOM 身份、缩放、选择、会话、任务和图片像素。主/独立 Agent 同步，冷重启保持。
4. 主窗、登录/设置、菜单、表单、编辑/查看、独立 Agent 使用正确 token；实际计算透明度、filter/backdrop-filter 和文本/焦点对比度。
5. 所有移动动作可经 UI/键盘到达；快捷键与“隐藏工具≠停用工具”不变，不删插件或改变授权。
6. 选图→上下文→图片参数→保存→继续输入→发送/直接生图分别调用原动作；运行中暂停/恢复/停止与错误入口可达。使用 loopback/fake，无真实付费请求。
7. 全局草稿取消不污染保存状态；即时保存失败能重试且防不安全关闭；折叠不丢旧主题/高级值，模型目录完整。
8. 检查焦点、Tab/方向键/Esc/中文输入法、长中文/长模型名；不能只断言 DOM 存在。
9. 按改动选专项：P1 以 test:glass-theme、test:settings-persistence、test:ui-foundation、aidebug:classic-themes 为入口；独立窗/生产变量变化补 test:agent-window 与相关 UI、test:production-symbol-compaction。P2 选设置/工作区/composer/automation 相关项。一个 quick GUI 加一个覆盖改动的专项，不机械全量。
10. 最终 package:win:unrestricted 的 production build 与打包成功，记录 EXE 路径/字节数/SHA-256；安全退出全部同名实例后品牌安装器 /S 原位安装，核对退出码/注册安装/已安装 EXE 和 ASAR。更新文档并普通 push upstream，核对远端提交。分别汇报构建、安装、文档、push；Release/二进制上传仍需另行授权。
