# 文字清晰度与画布 UI 改进计划

状态：用户于 2026-10-14 明确要求“按照计划进行执行”，本地实现与验证于 2026-10-15 完成。具体结果、报告及发布门禁边界见 [GOAL](../GOAL.md) 与 [PROGRESS](../PROGRESS.md)；下列原计划条目本身不替代实际完成证据。

## 目标与依据

让中文、小字号和缩放后的画布文字更容易读；降低玻璃背景对文字的干扰；让画布导航、常用工具与节点操作各有清楚的位置。沿用当前单画布、项目 Agent、成果/容器/需求节点和现有主题体系。

规划时已经复核的基线事实（实施前）：

- `01-base-controls.css` 定义了 12/13/14/15px 字号 token，但画布导航、悬停操作、小地图、快捷键和一些插件入口仍直接使用 9–10px。部分小字同时使用 760 字重。
- 主界面和独立 Agent 窗口的字体栈不完全一致；主界面强制 `optimizeLegibility`，节点额外强制 `geometricPrecision`。这些是需要对比验证的候选原因，不能单凭属性名判定为模糊根因。
- `canvasViewportTransform()` 已按设备像素对齐平移，并在交互结束后恢复 2D transform；现有清晰度方案应保留并实际复核。
- 本轮隔离基线 [before-default.png](../.diagnostics/electron/canvas-readability-2026-10-13T14-20-24-760Z/before-default.png) 显示：导航条盖住底部插件操作的一部分；55% 缩放时节点标题很小；密集文字区域存在明显斜纹背景。该截图只证明基线，不能作为修改后的验证。
- `CanvasInteractionToolbar` 只限制中心点的位置，然后 `translate(-50%, ...)`；尚未把工具条自身宽高纳入边界计算，靠边裁切需要用真实窗口复现。
- 已对照用户指定的 [basketikun/infinite-canvas](https://github.com/basketikun/infinite-canvas)，API 返回的 main 仍为 `3a6b64b602ad062b29fac66902ed18a7ef5fd9dc`，与本地参考文件一致。可借鉴其操作分组、较大点击区域、近实色快捷条和固定屏幕字号，不引入其业务节点或第二套画布状态。

## 验收标准（原计划）

- 字体：检查画布节点、菜单、工具条、Agent 正文/输入框、设置/代表弹窗和独立 Agent。主窗与独立窗的回退策略一致，不通过文字阴影、锐化滤镜或改变系统 ClearType 掩盖问题。
- 对比度：普通可读文字目标至少 4.5:1，大字与关键控件/焦点边界至少 3:1；禁用控件单独识别。测量实际合成底色，不能只比较未合成的 token。九个内置主题检查语义色，黑/白及代表玻璃主题保存渲染证据；自定义背景和极端透明度单列验证范围。
- 缩放：画布 50%、75%、100%、125%、150%、240%；检查滚轮/拖动停止后的文字与预览，检查固定操作条字号及低缩放标题。Windows 100%/125%/150% 像素密度优先用隔离 Electron 参数模拟，并明确它与真实多显示器切换的证据区别，不改变用户系统显示设置。
- 布局：1280×820 和最小 884×640；检查空画布、单图、容器、需求节点、长标题、多选，以及节点靠近画布四角的工具条。要求无意外横向溢出、关键按钮无遮挡，导航与插件操作不重叠。
- 交互：平移、缩放、适配、100% 还原、小地图定位、单选/多选、快捷栏查看/编辑/引用、菜单关闭与键盘焦点；主题切换保留画布、选择和项目状态。
- 性能：不增加画布常驻大面积模糊层或让所有节点在拖动时逐帧测量；优先复用已有视口和节点状态。实际观察拖动/缩放响应，若变更影响性能 owner 再扩大定向验证。
- 工程：样式在原 owner 中调整，不追加大段末尾覆盖。若修改主题 registry/启动投影，同步 bootstrap 与独立窗口镜像并运行 `test:glass-theme`；TypeScript 变化运行 `typecheck`；交付前必须完成 `corepack pnpm run build`。
