# SparkAI WorkSpace automation commands

> Generated from `commands.schema.json`; do not edit this file directly.

Invoke commands with `scripts/naimage.ps1 <command> -ArgsJson '<json>'`.

## Status and inspection

- `status`. Check the local authenticated bridge and renderer readiness.
- `app.state`. Return active project, conversation, Agent status, active run ID, pause state, selection, viewport, node summaries, and recent messages.
- `canvas.state`: `{}`. Return the active project and local canvas revision, selection, canonical relations, Requirement input bindings and revision/signature, canonical container membership, presentation layout membership, and per-node lock/busy details. Managed asset paths and automation credentials are never returned.

## Development debugging

- `debug.runtime-state`: `{}`. Return a bounded, redacted Main/Renderer runtime snapshot. Available only in local development or AIDebug mode; it never includes API keys, cookies, endpoint tokens, or absolute user asset paths.
- `debug.renderer-logs`: `{"limit":100}`. Read the most recent bounded Renderer console entries from the local diagnostic log after redaction. Development/AIDebug only.
- `debug.main-logs`: `{"limit":100}`. Read the most recent bounded Main-process diagnostic log after redaction. Development/AIDebug only.
- `debug.run-targeted-test`: `{"testName":"typecheck","timeoutMs":60000}`. Run one fixed, read-only repository test script and return bounded stdout/stderr. Arbitrary shell, paths, package installs, and user project mutations are not allowed.
- `debug.capture-window`: `{"label":"window","scope":"page"}`. Capture the focused SparkAI WorkSpace window into the bounded diagnostic directory. The caller cannot choose an arbitrary path or window.
- `debug.inspect-ipc`: `{}`. List registered IPC channel names and counts without exposing handlers, payloads, credentials, or user data.
- `debug.inspect-command`: `{"name":"name"}`. Inspect one shared automation command definition, including its surface and parameter schema, without executing it.

## Images and containers

For generation, editing, variants, cutout, redraw, and layer work, select the intended sources and use `agent.chat`. The Agent preserves provenance and creates results through the same runtime as the GUI.

## Responses and errors

Successful output is JSON with `ok: true` and `result`. Failures use `ok: false` and `error`. Retry a `rendererReady: false` status briefly. Never expose endpoint authorization data.

## Renderer lifecycle

Every Agent run and pending automation command is owned by the Renderer that dispatched it. If that Renderer closes or crashes, naimage immediately rejects its pending CLI commands, aborts its run, and prevents further dispatch without affecting other Renderer owners. Provider requests already accepted upstream continue draining under Main-process admission and may still complete or incur charges. Application shutdown aborts all runs before transports are dismantled.

## Goal dispatch safety

An explicit agent.goal or commerce.compose-set invocation authorizes upstream image charges. The Renderer still builds a complete preview and cryptographically random one-time receipt bound to the full request, frozen TaskScope, billing quote, active project, conversation, and issuing surface, then consumes it internally before dispatch. Changed inputs, stale scopes, changed costs, cancellation, and replay are rejected before provider dispatch. Goal execution uses the app's configured concurrency limit, but first serially probes 1-2 distinct SOURCE images, preferring different containers when available. Renderer windows share one Main-process Goal admission controller: queued probes take priority over new ramp waves, and admitted Goals fairly share the frozen process capacity. The app expands only after request acceptance, asset persistence, and result validation succeed; protected failures open a cross-Goal circuit. A bounded transport retry pauses every new ramp wave until the request settles, and closing a Renderer does not release its reservation until the real provider Promise drains. These safeguards stop only work that has not yet been dispatched. An upstream request already accepted by a provider may still complete and incur charges, so process-wide admission is not a cost guarantee.

## Commerce plan contract

For commerce.compose-set, languageCodes and targetLocales are mutually exclusive and every language code must come from the canonical commerce language registry. Unknown languages or supplying both fields fails before plugin composition, the internal Goal preview, or provider dispatch. TranslationItems uses the exact SOURCE expansion order and may override only a selected image-language cell; its normalized prompts are included in the frozen plan hash and prompt-material fingerprint. The structured plan, exact SOURCE boundary, and any unambiguous project SKU Catalog destination are frozen into the one-time internal authorization receipt and cannot be changed after dispatch begins. Successful results are reconciled from the persisted session into the frozen product, variant, or SKU target; ambiguous ownership or a Catalog revision conflict leaves the image on the canvas and returns a retry/manual-filing warning.
