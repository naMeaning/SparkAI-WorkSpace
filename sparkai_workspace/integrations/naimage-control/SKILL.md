# SparkAI WorkSpace Control

Read `app.diagnostics` for the last 300 sanitized production image/model events. `app.export-diagnostics` opens the user's native save dialog; it does not accept or return private file paths. Both commands are also available through Settings → Tools → Diagnostic logs. Logs omit credentials, prompts and media.

Use the bundled PowerShell CLI. Resolve paths relative to this Skill directory.

CLI JSON output is UTF-8 without a BOM, including non-ASCII project names and error messages. Decode stdout as UTF-8 when invoking from Node or other tools.

## Workflow

Use `project.package-export` with the active `expectedProjectId` and `preset:"share" | "archive"`; native dialogs choose the file. Share includes canvas, images, video, layers, generation parameters, relations, adoption and product data, but no project knowledge or conversations. Archive adds authored project knowledge and optionally `includeHistory:true`. Both preserve media file bytes, including embedded media metadata; only portable project metadata is scrubbed. These are not EXIF-cleaned media copies. New exports are streaming `.naimage` v4 ZIP containers with hash deduplication; `project.package-import` also reads legacy JSON packages and creates a new project identity. Credentials, caches, connections, active receipts and pending continuations are excluded; historical conversations grant no execution permission. Missing references or corrupt bytes fail instead of producing an apparently complete package. Neither command takes a caller-supplied path or calls a model.

Use `canvas.edit-image` to open the existing editor for one exact source. Modes are `edit`, `redraw`, `remove-object`, `replace-background`, `cutout` and `variants`; opening does not generate. A subsequent explicit GUI submission uses only `image_gen` and the current model/connection capabilities. Modify masks, protected-subject regions and reference annotations have different roles and stable identities. Masked edits locally composite and verify protected pixels; dimension mismatches fail without stretching. Cutout requires real alpha and a nonempty visible subject. Local processing failure never authorizes another generation. Outpainting is unavailable.

Use `comfyui.templates` and `comfyui.inspect` for a pre-existing localhost ComfyUI. `comfyui.import-template` opens a native API Format JSON picker and requires explicit `inputMappings` and `outputNodeId`; reviewed core nodes only, no cloud API/custom scripts or dependency installation. After user authorization, `comfyui.generate` takes a stable `submissionId`, exact template ID/hash, checkpoint, dimensions, seed and any required current-project source selectors. Only the template's declared generate/img2img operation is supported. Main freezes resolved seed, workflow, connection and sources before POST and journals the accepted prompt ID. Reconnect/query the same operation via `image.operations` / `image.recover`; unknown submission is never reposted, and the same ID is not assumed to be server-idempotent. `comfyui.cancel` deletes only this verified queued prompt; running cancellation is rejected unless targeted interruption is verified. Previews are not assets. Local image execution does not make the project Agent offline.

Read `project.context.get` for this conversation's actual frozen project knowledge and `project.knowledge.list` for current rules. Explicit “remember this for this project” intent authorizes `project.knowledge.save` with exact store/entry revisions; assumptions must remain suggestions until explicit `project.knowledge.promote`. Deactivate or tombstone with `project.knowledge.status`. Product/variant/SKU rules apply only to their returned scope. Editing knowledge never silently changes a running task or promotes FastMemory.

Use `project.results.search` for local combined usage/object/source/adoption/description filters and bounded stable pages. Match reasons distinguish intended Prompt content, user labels and evidence-backed observation; unobserved or stale content cannot be described as recognized. Searching makes no model call and changes no selection. Only after explicit use intent call `project.results.use` with returned exact targets and the current project/conversation; this binds composer materials and does not generate. An in-progress Agent uses the same owner via `project_context(use_results)` before first image dispatch; it cannot expand Goal scope. Always use current image settings for a new task and preserve the frozen knowledge/configuration for continuation.

Stable tasks use `agent.task.start`, `agent.task.get`, `agent.task.wait`, and `agent.task.answer`. Start returns a durable task/cursor after target/scope/save checks, while execution continues in the original GUI owner. Retry with the same project/conversation/submissionId and the same normalized request; a different request conflicts, and busy never becomes an implicit steer. If the caller times out or disconnects, query by submissionId or taskId. Do not invent a new submissionId merely to retry.

Structured creation uses `creation.requirements.get` and `creation.requirements.update`. Read the current revision before editing; save the complete goal, usage, stable deliverable slots, preserve/adjustable rules and acceptance conditions with `expectedRevision` (0 for the first creation). Every field must distinguish `source:"user"` from `source:"assumption"`. Keep a slot's `slotId` when renaming it. A revision conflict requires a fresh read and an explicit edit; do not overwrite another window's changes. Requirements belong to the project authority, shared by the main window, detached Agent, Runtime and CLI/MCP.

`agent.task.start` can explicitly bind `requirementId` together with `expectedRequirementsRevision` (at least 1). Without these fields, first acceptance freezes current requirements and a reconnect with the original submission reuses that original revision. Changing requirements does not rewrite an accepted task. New requirements need a new user submission; reusing an existing submission ID with an explicitly different revision conflicts instead of silently dispatching again.

Use `creation.acceptance.get` to read each result's generated, saved, deterministic file-check, AI-review and user-decision states separately. `creation.acceptance.check` only inspects existing local files for decode, dimensions, format and alpha; it does not call a model. An AI review must be backed by observed result pixels in the current Agent round and current requirements; missing, changed or uncertain evidence never means visual success. `creation.acceptance.decide` records the user's `adopt`, `reject` or `candidate` decision for the exact returned `assetId + occurrenceId + contentHash`. Adoption keeps the AI verdict intact and cannot bypass a hard file-check failure. Do not invent user adoption from a completed task or an AI pass.

For a requested partial revision, call `creation.revision.start` with the current `requirementId`/`expectedRevision`, a stable `submissionId`, exact `targets`, and `preserve`/`changes` string lists. Use the identities returned by acceptance, never visible image numbers, node order, paths or copied hashes. Top-level requirements apply to all selected targets; optional `targets[].preserve` and `targets[].changes` apply only to that exact target. Common `changes` may be empty only when every target supplies its own non-empty changes. For seven outputs where the user chose 2 and 5, include exactly those two identities and their individual edits. The existing durable task chain freezes them, retains original files and relations, and saves revisions as new results; it must not regenerate the other five. Retry the same normalized request with the same submission ID after a disconnect, and inspect its existing task receipt. This command can make upstream model requests only within the user's requested revision scope.

For precise region editing, select one acceptance result and use **精确区域修改** to open the existing paint editor. Saving the painted region creates a project-managed PNG mask and starts the same `creation.revision.start` task chain. A CLI/MCP caller may supply `targets[0].mask = {assetId, occurrenceId, contentHash}` using the managed identity returned by a prior mask save. The mask must belong to that exact target and conversation, have the original pixel dimensions, and pass actual-file validation. A masked revision accepts exactly one target. Never pass mask paths, URLs, data URLs or guessed identities to the revision command. The revision plan stores only the mask identity; TaskScope owns its frozen file material and image settings. Keep the same submission ID when querying or reconnecting so an existing region edit is never dispatched again.

Wait takes the last cursor as `afterVersion` and at most 30000ms. `timedOut:true` ends only the wait; continue get/wait on the same task. Older cursors get the newest snapshot; `TASK_CURSOR_EXPIRED` requires get. To answer, copy taskId, question.requestId as questionId, and the current version as expectedVersion, then send optionId or a custom answer. GUI and CLI share one-use consumption; stale answers never run. Material-upload questions use the original GUI picker. Receipts and idempotency entries are retained together without automatic expiry; capacity or corrupt storage fails closed. On restart, interrupted Agent work is not recreated: use listed imageOperations with the existing `image.recover` path for original accepted tasks/cached results. Never recreate an uncertain image POST. A completed execution is not a visual approval.

For unattended project creation, pass `parentDirectory` to `project.create`: an explicitly selected, existing absolute directory. Main creates a uniquely named child folder and never overwrites an existing project. Omit it to keep the native directory picker. Treat `canceled:true` as cancellation and any command error as failure; verify the new project with `canvas.state` before generating images.

## MCP server

`scripts/naimage-mcp.mjs` exposes every command in the same `references/commands.schema.json` as MCP tools and forwards calls to the authenticated loopback bridge. It does not implement a second canvas, Agent, billing, or persistence path. Configure an MCP client to start it with Node from this installed Skill directory:

```json
{
  "command": "node",
  "args": ["ABSOLUTE_SKILL_PATH/scripts/naimage-mcp.mjs"]
}
```

The server starts SparkAI WorkSpace from the installed connection metadata when necessary, keeps the endpoint token in memory, and never writes it to MCP output. Use `tools/list` to discover current commands instead of maintaining a separate tool list.

## Safety

- Never read, print, copy, or persist `.naimage-connection.json` or the automation endpoint token.
- Never treat MCP as a second business implementation. GUI, CLI, and MCP must continue to invoke the same shared command registry and production Renderer/Main actions.
- Never attempt to enable `debug.*` in a packaged production build, add arbitrary shell/path arguments, or use debug output to expose credentials, cookies, signed URLs, or absolute user asset paths.
- Never edit naimage project files directly while the app is running. Use the CLI so renderer state and persistence stay synchronized.
- Treat a workspace domain as a view and capability projection over the same project, canvas, session, assets, TaskScope, and Agent Runtime. Never create a parallel project state or claim that switching domains starts, stops, or bills a task.
- Import only a `SKILL.md` the user selected or placed in task scope. The first import boundary is one Markdown file up to 256 KiB with at most 24,000 instruction characters; sibling `scripts/`, `references/`, and `assets/` are not copied yet.
- Personal library entries are installation-local Requirement templates, not tool nodes or executable workflows. `requirement-library.use` creates a normal Requirement and must never be treated as implicit authorization to execute it.
- Treat returned local asset paths as user data. Do not modify source images outside naimage-managed project storage.
- `canvas.import-video` may read only the exact local files the user authorized. Never scan sibling folders, modify the sources, claim that import invokes `doubao-seedance-2-0-260128`, or report video-generation charges/progress/results. The current command only copies validated media into project-managed storage.
- `canvas.generate-video` creates exactly one provider task per invocation. Never loop it speculatively, automatically replace an `ambiguous:true` result, or use Chat Completions as a video fallback. A task with a remote ID is recovered by polling its journal entry; only safe status/download GETs may retry automatically.
- `social.*.plan` is non-billing and only creates a normal Requirement. `social.*.execute` is the explicit billing boundary: preserve its exact workflow identity and Requirement revision, and never turn a stale or ambiguous response into a second execution. Douyin video creation must keep the stable workflow idempotency key and independent video journal. `social.*.export` must remain native-picker mediated and accept no destination path.
- Scientific data stays in the active project's managed registry; never ask `research.data.import` to scan a directory or smuggle an absolute path into command JSON. `research.figure.plan` is non-executing. `research.figure.render` must preserve the selected Python/R backend for generation, preview, export and QA, must not invent data or statistics, and must never retry a completed local run merely because canvas landing encountered a revision conflict. Scientific status must not expose absolute paths, executable credentials or full data tables.
- `canvas.export-image` must remain user-authorized and native-picker mediated. Never claim that local format conversion spends image quota or regenerates the image.
- Ordinary `canvas.export-image` and Photoshop PSD export are separate UI/IPC paths. A normal PNG/JPEG/WebP/AVIF/TIFF export must never change PSD state or invoke a PSD worker implicitly; PSD export must not alter the ordinary export target or configuration.
- Image-group rename/replace/export commands accept project and node/asset identities only. Never expose an absolute path, signed URL, credential, or unmanaged asset locator to an Agent, CLI, MCP response, or project manifest.
- `commerce.export.package` must remain user-authorized and native-directory-picker mediated. Never add a destination path argument, bypass an integrity blocker, include rejected results, or mutate a managed source image.
- Concurrent exports to the same destination are serialized. If another operation creates the target after the Save dialog closes, naimage requires a fresh overwrite confirmation; never bypass that confirmation or retry as though the first export succeeded.
- Never bypass a rejected remote-backed asset by opening or downloading its raw URL. Localhost, private, link-local, reserved, mixed-DNS, and unsafe redirect targets are intentionally blocked before export.
- Goal mode respects the configured concurrency limit and starts with a serial probe of 1-2 distinct SOURCE images, preferring different containers when available. Renderer windows share one Main-process Goal admission controller: queued probes take priority over new ramp waves, and admitted Goals fairly share the frozen process capacity. Expansion starts only after requests, persisted assets, and result validation all succeed; protected failures open a cross-Goal circuit.
- Goal authorization remains prompt-bound and one-time internally. A changed prompt, stale canvas, different project/conversation, failed receipt consumption, or replay must produce zero provider dispatch.
- For `commerce.compose-set`, unknown language codes and simultaneous `languageCodes`/`targetLocales` input must remain zero-dispatch failures. The normalized plan and exact SOURCE boundary are frozen before dispatch.
- Probe and circuit-breaker safeguards prevent only undispatched work. Provider requests already accepted may still finish and incur charges even after pause, stop, or circuit break.
- A bounded transport retry pauses every new ramp wave until the request settles. Closing a Renderer does not release its reservation until the real provider Promise drains. Process-wide admission is not a cost guarantee; requests already accepted upstream may still be charged.
- A pending CLI command belongs to the Renderer that accepted it. If that Renderer closes or crashes, the command fails immediately and its undispatched Agent work is canceled; wait for a ready Renderer before retrying instead of leaving duplicate commands running.
- Retry a `renderer not ready` response briefly; do not start duplicate app processes repeatedly.

## Composer commands

Use `image.operations` to inspect the current project's image recovery records. Use `image.recover` with the returned `key` and `expectedProjectId` to query the original task or save its existing result. This action never creates another model request. Changed connection credentials block task queries; synchronous requests without a retained result or task handle cannot be recovered after restart. Saved outputs and repeated recovery use stable asset identities and are not duplicated on the canvas. A partial result preserves successful slots while the remaining slots stay recoverable.
