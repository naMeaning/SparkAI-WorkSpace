# 2026-07-16 状态、图片容器与性能收敛

## 本轮目标

- 动态工作状态只存在于右侧 Agent 主时间线；画布节点只显示静态类型、占位和必要终态。
- 并行图片继续使用统一图片容器，并依据真实图片比例确定展示顺序。
- 修复批量 AIDebug 在成果生成完成后的长时间阻塞。
- 用严格性能证据验证节点拖动、缩放与平移，而不是只看聚合绿灯。

## 已完成

- 节点头部状态收敛为 `单图`、`多图成果`、`图片组`、`连续系列`、`图片容器`、`图层组` 等静态类型；数量只在节点底部保留一次。
- 失败、部分失败、停止等必要终态仍可见；生成期间不显示节点级动态文案，待生成槽位使用无动画静态占位。
- AIDebug 新增 `canvasDynamicStatusQuietOk`：Agent 区域之外出现“正在生成 / 运行中 / 处理中 / 请求模型”等动态文案即失败。
- 图片容器继续共用 `imageGridPresentationForRatios`，按真实宽高比排序；单图、连续三图、并行十图、不同提示词图片组、归组、拆出、保存和继续生成均通过 GUI 专项。
- 20 张海报压力测试不再把每一步完整 GUI 状态重复序列化到 CDP；改为紧凑状态与阶段心跳。原先超过 10 分钟仍超时，现约 28 秒完成 20/20 张并生成完整报告。
- 节点拖动改为帧内瞬时 DOM 位移，放下时一次提交；重复选择不再触发无意义 React 更新。三轮产品性能中的拖拽帧 P95 从 146.5ms 降至 70.7ms，严格性能审计通过。
- 抽屉入场动画改为不越出视口的裁切淡入，修复 884px 设置抽屉瞬时右溢出 18px。

## 2026-07-16 横向推进：几何稳定、长会话与真实流式输出

- 密集图片容器不再通过 `scale(1.06/1.08)` 放大 hover 项。高亮改为不改变网格几何的边框、底色与阴影，避免六图、十图容器的缩略图覆盖相邻行。
- 节点聚焦由多组 `0/140/360ms` 与 `0/180/420ms` 延迟修正收束为 DOM 提交后的一次定位。选择成果或生成新成果后，画布不再被连续拉动；AIDebug 双帧也不会因为迟到的定位定时器发生漂移。
- 右键“创建生图工作”窗口由 620px 固定高度收紧到 540px，提示词编辑区仍保留至少 150px，减少空白并保持 884px 工作台可用。
- 500 条 Agent 历史的性能契约统一为“运行时保留 500 条、DOM 默认显示最近 80 条”。旧性能门不再错误等待 500 个 DOM 节点；本轮实测该阶段由约 30 秒误等待降至约 102ms，输入响应约 11ms。
- AIDebug 的 1000 增量流式夹具改为独立累积缓冲和约 30fps 提交，避免调试控制面自身排入 1000 个 React updater。相同的 32ms 批处理已下沉到真实 Agent `model-thinking-delta` 与 `assistant-message-delta` 链路；工具开始、思考结束和最终回答前会强制冲刷，消息顺序不变。
- 模型缓存仍由主进程统一维持 60 秒；设置页第 5 次主动获取即触发真实刷新，修复原先第 6 次才刷新的边界错误。缓存来源与 TTL 继续只作为内部诊断数据，不显示给用户。
- 生产包当前为 JS `639,954 B`、CSS `173,779 B`、总计 `864,322 B`，仍在正式门限内，且无 AIDebug 控制面泄漏。

本轮已通过：`typecheck`、Agent 文本协议、原生工具协议、工具时间线、性能证据审计 13 项单测、生产 bundle 自检。完整性能 GUI 复验保留到最终统一门禁，避免在横向推进期间反复消耗同一专项。
