# AIDebug 真实可靠性契约

更新时间：2026-07-12

## 目的

AIDebug 的“全绿”只表示已声明的断言成立，不能自动等价为界面真实可用、视觉合理或交互没有误判。今后的交付结论必须同时满足功能、状态、手势、视觉和证据五层门槛；任何一层缺少证据都应记为 `unknown` 或失败，不能用另一层的成功补绿。

## 五层证据

### 1. 功能结果

- 请求确实生成、移动、归组、拆组、重组、保存或编辑了目标对象。
- 结果数量、类型、资源路径、文件字节、父子来源关系和图层归属符合预期。
- 只允许预期字段发生变化；坐标操作不能悄悄改写 Prompt、资源、因果关系或图层顺序。

### 2. 状态一致性

- 同时记录并比较 `ref`、React state、画布投影、Canvas nodes、虚拟化渲染结果和 DOM。
- 报告缺失 ID、意外 ID、顺序漂移、重复 ID、孤儿 layout group、一个成员进入多个组等问题。
- 断言前后至少跨稳定帧采样；异步更新尚未稳定时不得判绿。

### 3. 真实手势

- 每次手势使用唯一诊断 ID，记录起点、终点、距离、阈值、轨迹采样、Pointer/Drag 路由和耗时。
- 每个轨迹点记录 `elementsFromPoint()` 命中栈、候选目标、吸附状态、客户端坐标、世界坐标和当前缩放。
- 保存源/目标操作前后的几何、computed style、z-index/stacking chain、布局组与节点状态差异。
- 离屏目标必须先移动或缩放到可交互视口；找不到 DOM 不能退化成直接调用数据函数并声称真实手势通过。

### 4. 真实视觉

- 分离“总览拓扑”和“选中成果可读性”：总览允许缩小，但必须另有聚焦截图证明关键节点在可用缩放下可读。
- 检查节点/弹窗/输入区重叠、遮挡、裁切、可见比例、标题可读性、缩略图有效像素面积、容器自适应网格和 Agent 面板占位。
- 检查选中高亮、吸附反馈、线与节点层级、图层透明叠加、窄屏排版和 hover/展开状态。
- DOM canvas 像素读取失败时必须保留失败事实；CDP/原生截图像素采样只能作为独立证据，不能覆盖原失败。

### 5. 证据质量

- 每个场景同时保存请求视口、实际视口、DPR、应用缩放、画布缩放、截图来源、截图尺寸和 SHA-256。
- CDP 截图与原生窗口截图应尽可能双采集；尺寸异常、回退占位图、跨域采样失败或截图缺失都使证据层失败。
- 报告分别输出 `functionalOk`、`stateOk`、`gestureOk`、`visualOk`、`evidenceOk`，最终 `ok` 只能是五者的合取。
- 不得让多个场景共享同一个可变 `suite` 对象；后续专项不能反向改写之前场景的结果。

## 场景级最低参数

每个关键场景至少包含：

- `scenarioId`、开始/结束时间、稳定等待耗时。
- 请求和实际窗口尺寸、DPR、Canvas viewport、缩放。
- 源节点/目标节点 ID、资源索引、路径指纹、因果关系、z-order。
- 操作前后六层状态快照与允许变更清单。
- 手势轨迹、命中栈、阈值、候选吸附、最终路由和失败原因。
- 目标节点/弹窗几何、computed style、stacking chain、遮挡与重叠明细。
- CDP 截图、原生截图、像素区域报告与证据文件哈希。

## 交付规则

1. 自动断言全绿后，仍需人工查看关键截图：画布总览、单图聚焦、多图容器、图层叠放/展开、节点编辑器、Agent 长时间线与窄屏。
2. 自动结果和截图冲突时，以真实截图和可复现交互为准，修正断言而不是降低标准。
3. 无法自动判断审美、信息层级或操作直觉时，明确标记“需要人工验收”，不得写成已通过。
4. 每个大阶段完成后保持 GUI 运行，供用户做真实体验验证；用户反馈继续进入下一轮回归。

## 独立证据复核

GUI 套件完成后还必须运行：

```text
pnpm run aidebug:evidence -- --report=<本轮 report.json>
```

该复核不读取套件自己的“全绿”结论作为事实，而会重新核对实际截图文件与素材文件。以下任一情况都会判失败：

- 缺少请求窗口、实际窗口、renderer viewport、DPR、画布缩放或截图哈希/尺寸；
- “当前选中”浮层、Agent 面板或其他表面真实遮挡选中成果；
- 多图容器展示三张以上图片时，文件哈希不足以证明至少三张实际不同的素材；
- 分层 PNG 的非背景层重复使用同一个文件内容，或没有可验证的透明像素；
- 套件 `ok` 与功能、状态、手势、视觉、证据五层的合取结果不一致。
