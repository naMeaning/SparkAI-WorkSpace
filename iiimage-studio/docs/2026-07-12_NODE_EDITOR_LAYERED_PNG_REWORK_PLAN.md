# 节点编辑器与分层 PNG 全链路整改计划

更新时间：2026-07-12

## 一、真实失败复盘

最新项目 `project-mrgmjtoy-g8qzxc` 中，用户明确要求下一张 JAVA 海报按“标题、文字、人物、人物道具、前景、后景”拆成六层。实际记录显示：

- Agent 调用了 `image_gen(operation=generate)`，没有调用 `operation=layers`。
- 工具 Prompt 只要求画面“视觉上便于分离”，最终仍是一张扁平不透明 PNG。
- 节点 B 只有 1 个普通图片资产，没有 `layerComposition`、组编号、逐层 PNG、合成预览或重组结果。
- 根因之一是分层意图识别只匹配“分层 + PNG/绘制/生成”等窄表达，没有识别“带分层的”和连续多个“某某一层”。
- 即使正确进入 layers，当前缺少对“精确 N 层全部成功”的硬门槛；部分图层失败仍可能建立不完整图层栈。
- 基于当前成果继续做分层时，layers 路径只继承 `parentId`，没有自动把来源节点图片作为视觉参考。

## 二、历史准确要求

- 分层成果不是一张“看起来层次清楚”的图，而是 N 张同尺寸 PNG 图层和一张重组后的完整成图。
- 除最底层背景外，人物、道具、前景、标题和文字等层必须具有真实透明像素。
- 图层从底到顶拥有稳定顺序、唯一组 ID 和可读组编号，不同作品不得混组。
- 每个图层必须是一个真实、独立的图片节点；六层成果必须落为六个节点，不能再由一个节点内部模拟六层。
- 同组节点共享唯一组 ID、可读组编号、层序和统一锚点，初始坐标完全相同；透明 PNG 叠加后形成完整成图。
- 用户通过节点外侧错层标签选择和拖出任意一层；被拖出的节点恢复普通图片成果卡片，其余层继续留在原锚点。
- 打乱或展开后，右键任意成员执行“图层重组”，整组节点按原始锚点和层序归位。
- 图层组成员之间不创建内部关系线；只有最底层可保留作品来源关系，避免重复溯源线。
- 必须保存合成预览、逐层素材和重组校验结果，不能只写元数据或伪造完成。

## 三、本轮实施

1. 扩展自然语言分层意图识别，覆盖“带分层”“某某一层”连续列举等真实表达。
2. 强化 Agent Prompt 与 image_gen schema：layers 必须提供按底到顶的完整 `layerPlan`，用户列出的层不能合并、遗漏或改成普通 generate。
3. 禁止静默把错误 operation 改成 layers；错误调用返回明确参数契约错误，让 Agent 自己修正 tool_call。
4. layers 自动读取 `parentId` 对应成果图片作为参考，不要求模型猜本地路径。
5. N 层必须 N 层全部生成成功；任何一层失败、缺资产、透明度不可靠或重组不完整均明确失败。
6. 分层运行时结果拆成 N 个独立图片节点；每个节点只持有自己的一个 PNG、提示词、编辑器、菜单和持久化记录。
7. 叠放态隐藏普通卡片壳、重复标题、Footer、连接头和缩放柄，节点尺寸严格跟随合成画布宽高比；外侧错层标签承担选择、层序和拖出入口。
8. 拖出单层只修改该节点的 `detached`、位置和卡片尺寸；“展开图层”批量铺开成员，“图层重组”重新合成校验图并让所有成员回到共同锚点。
9. 旧项目中的单节点 `layerComposition` 在读取时自动迁移成多个 `layerGroup` 独立节点，不继续保存旧结构。
10. 节点编辑器统一 Header、内容区和 Footer；当前图层信息、同组成员切换、取消、保存、保存并继续、图层文件夹、展开和重组全部使用统一按钮体系。

## 四、验收

- 用最新真实用户表达验证 Agent 首次或纠错后实际执行 `operation=layers`，而不是普通 generate。
- 六层计划生成 6 个唯一画布节点、6 张同尺寸图层 PNG、1 张共享预览和 1 张共享重组图；任何节点都不得残留 `layerComposition`。
- 5 个非背景图层均有真实 alpha，重组绘制数必须为 6/6。
- 六节点初始拥有相同组 ID、相同锚点和 1..6 稳定层序；除最低层外不建立内部连线。
- 鼠标真实拖动人物层标签后仅人物节点脱离；其余五层坐标不变。右键重组后六节点全部回到共同锚点并恢复叠放态。
- session.json 必须持久化六个唯一节点、每节点一个 PNG、同组元数据和归位状态；不得回退为单栈节点。
- 节点编辑器所有操作按钮具备统一尺寸、边框、填充、hover、focus、disabled 和图标布局；1280 与最小工作宽度无裁切。
- TypeScript、正式构建、AIDebug 节点编辑器专项、分层专项和真实 Agent 分层链路全部通过。

## 五、执行结果

- 历史原句“标题一层、文字一层、人物一层、人物道具一层，背景分为前景和后景，共六层”已准确识别为 6 层；错误调用 `generate` 会返回 `operation=layers` 契约错误，3 层计划也会因与用户指定 6 层不一致而拒绝执行。
- 真实 `gpt-5.6-sol` Agent 已验证会自主调用 `image_gen(operation=layers)`，提交完整六层计划，并生成预览、6 个独立图层和重组结果。
- 修复 SSE 收到 `[DONE]` 后仍等待连接关闭的死锁；真实 Agent 工具专项已通过。
- 为单次 Image 2 请求增加独立硬超时，避免某个上游图片请求永久拖住整个分层任务。
- 六层 AIDebug 专项已验证：8 个项目文件、5 个非背景 alpha 图层、全部同尺寸、六个唯一节点、真实 Pointer 单层拖出、整组重组、六节点持久化、独立编辑器与最小工作宽度均通过。
- 真实图层测试发现前景色键受边框平均色污染，重组图一度出现大面积品红。背景估计已改为边框中位数，并增加强品红残留硬门槛；对该次真实原始前景复算后，透明区域为 78.36%，强品红残留 0.11%，重新合成整图强品红比例 0.32%。
- 最终 `node --check`、严格 TypeScript、正式构建、Agent-only GUI 回归与六层 GUI 专项均通过；Vite 仅保留既有的大 chunk 警告。

## 六、独立图层节点架构返工结果

- `WorkflowNode` 新增 `layerGroup`，保存组 ID/编号、总层数、当前层序、层角色、合成尺寸、统一锚点、脱离状态以及共享预览/重组资产。
- `workflow.layer.group` 与兼容的 `workflow.layer.merge` 不再走普通单节点创建逻辑；前端完成透明化和重组校验后，一次创建 N 个独立节点。
- 非背景层仍执行真实 Alpha 处理和硬校验。最新六层专项中五个非背景层透明区域均约为 75.4%，背景透明区域约为 1.1%，满足背景不透明、其他层可叠加的要求。
- 解决“图层分开但看起来仍不透明”的 UI 根因：叠放节点不再沿用带 Header/Footer 的普通长卡片，而是严格按原图宽高比显示透明画板；拖出后才恢复完整编辑卡片。
- 叠放成员右侧显示有层序、名称和角色的错层标签，并按背景、前景、主体、装饰、文字使用不同强调色；选中节点保留清晰高亮。
- AIDebug 的碰撞和标题可读性规则已理解分层组：同组未脱离节点的重叠是合法叠加，不再误报普通节点碰撞；标题可读性检查外侧图层标签。
- 兼容迁移、独立节点运行时、单层拖出、批量展开、整组重组、编辑器、项目文件夹、session 持久化和 Agent 主链均形成闭环。
