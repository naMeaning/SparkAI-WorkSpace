# Round 2：图片管线性能、渲染隔离与电商闭环

更新时间：2026-07-12

## 本轮用户价值

这一轮不继续堆功能入口，而是让现有的单图、多版、批量、连续系列、图片容器、编辑和导出在真实项目规模下仍然顺滑、可恢复、可解释。目标链路是：

`项目原图 → 受控资产库 → 缩略图 → 画布/容器 → 原图查看与编辑 → Agent 原生工具调用 → 新成果 → 保存/PSD → 重启恢复`

图片在画布中只读取适合显示尺寸的缓存版本；查看器、编辑器、Image Gen 参考图和导出始终使用原图。任何缓存损坏都只能影响预览，不能修改或替代原资产。

## P0：项目缩略图缓存

### 数据契约

- 原图身份由受控项目路径、文件大小和 mtime/内容摘要共同决定；缩略图键必须随原图变化失效。
- 缩略图位于项目 `.iiimage/thumbnails/`，不写入用户原图目录，也不进入成果节点的权威资产路径。
- 第一阶段只建立一个 512 px 长边、自动旋转、保留透明通道的画布预览规格；不要提前建立多规格缓存体系。
- PNG 透明图输出 PNG，JPEG/无透明 WEBP 可输出质量受控的 WebP；失败时回退原 `assetUrl`，不能让节点消失。
- 同一缩略图并发请求去重；生成使用有限并发或独立 worker，禁止在 Electron 主线程同步解码大图。
- 原图删除或变化时允许惰性重建；缓存清理按项目范围执行，不跨项目共享可变路径。

### UI 使用边界

- 画布普通节点、图片容器成员、图层轨道缩略图和查看器底部条使用 thumbnail。
- 图片查看器主图、节点编辑器主预览、AI 抠图/AI 重绘画布、Image Gen 参考图和所有导出使用 original。
- 当前选中或正在拖动的节点不能因缩略图异步切换发生尺寸跳动。

### AIDebug 证据

- 新增 24 张 4K 混合 PNG/JPEG/WEBP fixture，记录原图总字节、缩略图总字节和实际 `<img>` 请求 URL。
- 首次打开允许生成；二次打开必须命中缓存且不重复生成。
- 改变一个源文件后只重建对应缩略图。
- 证明查看器主图和 PSD/另存仍引用原图，不误导出 thumbnail。
- 测量首次/二次 hydrate、图片 `load/decode` 数量、heap 和 Long Task；任何 unknown 指标不得作为绿色结论。

## P1：Renderer 与 Agent 状态隔离

### 先补观测

- 为画布节点区、Agent 时间线、输入区分别增加开发态 render/commit 计数，不进入正式包。
- 记录一轮 200 个流式 delta、10 个图片进度事件、60 秒计时器期间三个区域各自提交次数。
- 只有拿到重渲染来源后再拆组件，不能用主观感觉宣称优化。

### 小步拆分

- 将 Agent 消息列表、工具时间线和运行计时器移出工作台根组件的高频更新路径。
- 计时器只更新需要显示秒数的最小组件，不每秒重绘画布节点。
- 流式正文按动画帧或短批次合并提交，但不得丢字符、改变工具调用顺序或延迟最终完成态。
- 画布节点组件建立稳定 props 与 memo 边界；节点位置拖动只更新相关节点和线路，不重绘 Agent 面板。
- 组件拆分不能改变当前 AIDebug hook 的真实性；测试 hook 只能读真实状态，不能成为第二套业务实现。

### 完成门

- 200 个流式 delta 期间未改变节点的画布提交次数显著下降，并记录优化前后同 fixture 数字。
- 60 秒工具计时期间画布节点不发生每秒整区提交。
- Agent 文案、独立工具调用/完成卡片、折叠 Prompt、Experience 隐私规则和滚动位置无回归。

## P1：导入和项目保存异步化

- 当前批量导入仍包含同步目录遍历、`readFileSync + sha256` 和复制；下一步迁入 worker/异步流式管线。
- 文件夹导入按稳定顺序枚举，哈希与复制有限并发，支持取消和真实进度；相同内容去重仍必须成立。
- 主进程只协调项目身份、目标路径和最终提交，不逐张同步读取大文件。
- Renderer 保存请求显式携带单调 `sessionRevision`；主进程继续以 `projectId + revision` 跳过迟到写入。
- 项目切换、退出和创建新项目时显式 flush 对应队列；未知 projectId 继续拒绝，不回退当前项目。
- 用 500 张混合文件、重复文件、损坏图片、目录和符号链接 fixture 验证 UI 可响应、结果顺序、跳过统计、取消及跨项目隔离。

## P1：production-like 性能桥

- 正式包继续完全移除完整 AIDebug。
- 建立只在测试构建启用的小型 performance bridge，只暴露性能 fixture 所需的真实创建、视口、提交计数和保存完成信号。
- 新增正式构建近似场景，和开发态报告分开命名、分开预算，不混合宣称。
- BrowserWindow bounds 取不到时保持 unknown；不能再用 renderer outer/inner 回填。

## P2：电商任务真实闭环

优先复用 `COMMERCE_USE_CASE_MATRIX.md` 的六组样例，每个场景都必须由 Agent 原生理解后调用公开 Image Gen Schema，不在外层做关键词路由或 synthetic user 修正。

### 第一批

1. 单商品主图：一张运动鞋生成单图和 4 个版式。
2. 多角度：同一商品生成正面、侧面、背面、细节四张独立资产。
3. 文案置换：咖啡杯海报仅替换目标文字，保留商品和版式。
4. 主体置换：香水瓶替换主体，保留背景、阴影、构图和已有文字。
5. 服装上身：平铺服装 + 成年模特参考，生成 3 种姿态，保留图案、颜色和版型。
6. SKU 裂变：同款 T 恤 6 种图案，容器展示且每张可拖出、编辑、另存和导出 PSD。

### 每个场景的硬证据

- 用户原句、选中节点、参考图 `role/purpose` 与容器 `assetIndex`。
- 模型原生 tool call、标准化后参数和真实工具结果。
- 不出现外层强制 tool choice、关键词路由、自动改写用户意图或失败后 synthetic user。
- 每张结果是独立资产，不用拼贴图冒充多图。
- 画布节点/容器、Prompt、关系、继续编辑、另存、PSD 和重启恢复完整。
- 对文字准确、主体保持、服装细节和多角度一致性如实记录；Image 2 做不到时返回限制，不伪造通过。

## 执行顺序

1. 关闭普通图片 PSD 与分层回归，建立新的全绿基线。
2. 实现缩略图缓存最小闭环，并扩展真实性能 fixture。
3. 补 Renderer 分区提交计数，再做 Agent/画布渲染隔离。
4. 异步化文件夹导入和前端显式 session revision。
5. 建立 production-like 小型性能桥。
6. 逐个执行六类电商真实样例；每完成一个都回归通用单图/多版/容器/导出，而不是等最后一次性补测。

## 禁止回归

- 不改变原图，不让缩略图成为权威资产。
- 不恢复手动工作流、Agent 节点、子 Agent 或功能岛。
- 不增加外层强制重试、关键词路由或隐藏系统纠错。
- 不放宽现有选择高亮、容器真实拖拽、分层透明度、重组、线路、登录、会话/FastMemory 隔离和 evidence audit 门。
- 不用测试 fixture 的小图片、DOM 存在或内部函数返回冒充真实用户性能和交互证据。
