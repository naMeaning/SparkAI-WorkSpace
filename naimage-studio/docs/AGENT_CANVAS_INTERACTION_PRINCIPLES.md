# naimage Agent、画布与编辑器交互方针

更新时间：2026-07-12

## 一、唯一交互模型

- 右侧 Agent 是唯一智能控制中心；画布只承载图片成果、图片分组和成果关系。
- 用户必须能够看见 Agent 的简短意图、工具用途和实际传给图片模型的 Prompt；设置页允许用户主动打开主 Agent 纯文本 Prompt 编辑器。Prompt 使用无 entries 的纯文本存储，工具 Schema、compact 摘要与 Prompt 编辑器保持独立。普通时间线不得展示数据库 entry id、内部路由、缓存或实现细节。
- Agent 可以简短说话，也可以直接调用工具；工具卡必须补足“正在做什么”的可理解反馈，不能完全沉默，也不能用重复日志淹没聊天。

## 二、项目、会话与记忆隔离

| 操作 | 保留 | 清空/隔离 |
| --- | --- | --- |
| 清理当前聊天 | 当前项目画布、其他历史会话 | 当前会话消息、运行上下文、compact 摘要、当前会话 FastMemory、附件草稿 |
| 新建会话 | 当前项目画布、旧会话历史 | 新 conversationId、空消息、空上下文、不得读取其他会话 FastMemory |
| 新建项目/画布 | 其他项目完整保留 | 新 projectId、空画布、新 conversationId、空会话、不得读取其他项目 FastMemory |
| 切换历史会话 | 当前项目画布 | 只加载目标 conversationId 的消息与记忆，不混入刚才会话状态 |

- FastMemory 必须同时按 `projectId + conversationId` 作用域读取和写入。
- Agent 标题栏提供 FastMemory 编辑入口；编辑器只读写当前项目当前会话，不能修改 Prompt、工具 Schema 或其他会话记忆。
- 无作用域的旧 FastMemory 不允许自动注入新会话或新项目，只能作为迁移/显式读取输入。
- 清理聊天是危险操作，必须确认；成功后只给用户友好反馈，不显示内部文件或 entry id。

## 三、Agent 工具时间线

- 工具调用前允许显示模型正文，例如“收到要求，这些建议有效，我需要学习这次绘画经验。”
- 工具卡统一格式：`正在使用工具 · Experience`，下一行直接显示 Brief 内容，不显示 `Brief` 标题。
- Experience 成功显示“记录经验成功”；失败显示可理解错误。禁止展示 `fastmemory 已写入 fmem-...`。
- Image Gen 工具卡显示：
  - 单条运行状态 `Image Gen 正在绘图 Ns`；
  - 一句 Brief；
  - 一个默认折叠的“生成提示词”区域；
  - `items` 多 Prompt 时逐项折叠显示，用户可独立展开。
- 工具卡不得因为 `tool-start / poll / image-request / tool-done` 重复生成多条相同记录。

## 四、画布选择与图片归类

- 单选或框选建立后，普通点击空白画布、平移画布、打开查看器不得取消选择。
- 只有“当前选中”区域的 X、删除节点、切换项目/会话等明确语义可以取消选择。
- 所有选中节点必须保持可见高亮，与右栏列出的节点完全一致。
- 拖动节点标题/外框用于移动节点；标准单图的图片内容也可移动节点，进入另一图片的明确吸附区后才执行画布内归组。多图容器内部图片保留成员重排/取出手势，两类入口不得互相抢占。
- 不提供 Windows 系统拖出把手。成果导出统一使用右键“另存为”、图片查看器下载和节点编辑器“另存为”，避免与画布内移动、归组和图片查看手势冲突。
- 单图拖到另一张单图：目标升级为图片容器，接收两张图片；只改变 `layoutGroups` 视觉归类，来源节点和生成因果保持不变。
- 单图拖到容器：加入容器。
- 容器拖出图片：恢复为标准单图显示；容器剩一张时自动解组，剩余图片继承原容器位置，避免伪容器和节点跳位。
- 分层 PNG 节点不得加入普通图片容器，也不得直接拖出为系统文件；先“合并为新成果”后，合并图才进入普通图片拖放与导出规则。

## 五、AI 抠图、AI 重绘与节点编辑器

- “魔法抠图”统一改名为“AI 抠图”。不得点击即生成；必须先打开选择界面，让用户涂抹大致主体区域并填写可选描述，再调用 `image_gen(operation=cutout)`。
- “区域重绘”统一改名为“AI 重绘”。两者共用同一套扁平化图片编辑弹窗骨架：左侧/上方画布充分占用空间，右侧要求区填满可用高度，减少嵌套边框。
- 单击图片打开查看器；双击图片或双击节点标题打开统一节点编辑器。
- 右键菜单必须提供“编辑节点”。节点编辑器只保留标题与完整 Prompt；用户直接修改完整 Prompt 后可保存，或“保存并继续生成”，不再维护语义重复的“继续生图要求”第二输入框。
- 所有编辑器使用一致的 Header、内容区、操作区、间距、按钮和错误状态，不为每种节点制造互不兼容的弹窗。

## 六、验收原则

- 数据隔离必须通过跨会话、跨项目、清理后重启测试。
- UI 必须通过 1280 宽和最小工作宽度截图检查。
- 拖拽必须使用真实 pointer/drag 事件验证，不能只调用内部函数。
- Agent 时间线必须用真实自然语言请求验证正文、Brief、Prompt 折叠和隐藏内部 ID。
- 每轮至少通过 TypeScript、构建、AIDebug GUI；关键 Agent 行为还需真实模型验证。
- AIDebug 全绿只是自动化基线，必须同时审查真实截图、有效像素面积、遮挡/重叠、状态层一致性和手势命中证据；具体遵循 `2026-07-12_AIDEBUG_RELIABILITY_CONTRACT.md`。
