你正在修改一个已经投入开发的 Windows Electron AI 无限画布软件。

# 三、四大工作模式

新增统一类型：

```ts
export type WorkspaceDomain =
  | "general"
  | "commerce"
  | "social"
  | "research";
```

需要有一个明确的模式注册表：

```ts
interface WorkspaceDomainDefinition {
  id: WorkspaceDomain;
  title: string;
  description: string;
  icon: string;
  pluginIds: string[];
  defaultPrompt?: string;
  availableTools: string[];
}
```

注册四种模式：

```text
general  通用创作
commerce 电商创作
social   社媒创作
research 科研绘图
```

模式只是当前工作台能力的投影，不改变项目的底层数据结构。

模式切换时：

* 不卸载无限画布
* 不清空选择
* 不删除节点
* 不重建项目
* 不重新初始化 Agent Runtime
* 不丢失正在运行的任务
* 不改变已有 SOURCE / REFERENCE
* 不自动调用模型
* 不产生费用

模式只影响：

* 顶部和底部工具入口
* 左侧素材轨的快捷分区
* 新建任务模板
* Agent 默认领域上下文
* 推荐工作流
* 当前可见插件工具
* 空项目引导内容

# 四、用户切换方式

## 4.1 顶部模式切换器

在当前工作台顶部增加一个紧凑的 `WorkspaceDomainSwitcher`。

显示当前模式，例如：

```text
通用创作 ▾
```

点击后展示：

```text
通用创作
电商创作
社媒创作
科研绘图
```

每个选项显示：

* 图标
* 名称
* 一句话说明

不要使用占据大量空间的常驻四卡布局。

在普通工作状态下，模式切换器应保持紧凑。

## 4.2 新项目入口

新建项目时展示四个入口卡片：

```text
通用创作
适合自由图片、视频和画布 Agent 任务

电商创作
适合商品套图、多语言、SKU 和平台导出

社媒创作
适合小红书图文和抖音短视频

科研绘图
适合数据图表、论文插图和多 Panel 图
```

选择后仍进入相同无限画布，只设置项目初始模式和推荐模板。

## 4.3 快捷键

在不与现有快捷键冲突的前提下支持：

```text
Ctrl/Cmd + 1  通用创作
Ctrl/Cmd + 2  电商创作
Ctrl/Cmd + 3  社媒创作
Ctrl/Cmd + 4  科研绘图
```

如果现有快捷键冲突，使用当前插件快捷键冲突检测机制，不能强制覆盖。

## 4.4 状态持久化

为项目保存可选字段：

```ts
workspaceDomain?: WorkspaceDomain;
```

旧项目没有该字段时默认：

```text
general
```

需要同步更新：

* 共享类型
* session normalizer
* 默认 session
* 保存与恢复
* 自动化快照
* 独立 Agent 窗口的脱敏快照
* 项目导入兼容

不得因此升级或破坏已有资产身份、节点结构和项目包。

# 十、首次 AskUser 引导

复用现有 Agent `ask_user` 工具。

不要额外开发独立的问卷引擎。

## 10.1 使用原则

只有在以下情况调用：

* 用户第一次进入某个工作流
* 缺少决定输出方向的关键信息
* 素材范围存在歧义
* 用户必须选择创作方向
* 可能产生明显费用
* 操作不可逆

不得询问：

* 用户已经明确提供的信息
* 可以从当前选择和画布推断的信息
* 可以使用合理默认值的信息
* 只是为了让流程显得完整的信息

每次只询问一个维度。

每个问题提供 2～4 个可操作选项，并允许补充文本。

普通工作流总问题数尽量不超过 3 个。

## 10.2 社媒首次引导

进入社媒模式但未选择平台时询问：

```text
这次准备制作哪种内容？

- 小红书图文
- 抖音短视频
- 两个平台都需要
- 先整理素材
```

小红书必要问题按需询问：

```text
这篇内容主要介绍什么？
希望读者看完后做什么？
这次使用哪些素材？
```

抖音必要问题按需询问：

```text
这条视频主要讲什么？
准备做成哪种形式？
视频大约需要多长？
```

用户回答后必须继续执行，不能重复询问。

## 10.3 首次引导状态

增加一个轻量、非敏感的安装级设置：

```ts
interface WorkflowOnboardingState {
  social?: boolean;
  xiaohongshu?: boolean;
  douyin?: boolean;
  research?: boolean;
  commerce?: boolean;
}
```

这里只记录是否完成首次引导，不保存用户内容。

即使已经完成引导，关键信息确实缺失时，Agent 仍可调用 `ask_user`。

# 十四、科研安全执行器

```text

```

它只负责项目范围内的科研绘图任务。

限制：

* 运行目录限定在项目受管临时目录
* 只允许 Python 或 R
* 每个任务只能选择一个后端
* 设置执行超时
* 设置输出文件数量和大小限制
* 禁止访问用户任意目录
* 默认禁止网络访问

* 捕获 stdout、stderr 和 exit code
* 输出脚本、图片和受限日志
* 完成后把成果复制到项目资产目录
* 失败时不伪装成功

第一版优先支持已有环境中常见的：

```text

numpy
matplotlib
scipy
```

```text
ggplot2
```

缺少依赖时明确告诉用户，并提供安装指导。

科研图片导出支持：

# 十七、Agent 领域上下文

根据当前 `workspaceDomain` 向 Agent 注入简短领域上下文。

不要创建四个 Agent Runtime。

例如：

```ts
function workspaceDomainPrompt(domain: WorkspaceDomain): string {
  switch (domain) {
    case "commerce":
      return COMMERCE_DOMAIN_PROMPT;
    case "social":
      return SOCIAL_DOMAIN_PROMPT;
    case "research":
      return RESEARCH_DOMAIN_PROMPT;
    default:
      return GENERAL_DOMAIN_PROMPT;
  }
}
```

领域 Prompt 必须保持简短，详细流程应通过插件 Skill 按需加载，避免每次对话注入大量无关内容。

Agent 应根据：

* 当前模式
* 当前选择
* TaskScope
* 已启用插件
* 用户意图

决定是否加载对应 Skill。

切换模式不能清空已有对话。

* 返回真实成功或失败
* 不伪造 Renderer 成功

计费命令必须明确返回：

* 请求数量
* 是否已经派发
* 是否可能产生费用
* 是否处于 ambiguous 状态

科研渲染命令必须返回：

* 后端
* 脚本资产
* 输出资产
* 执行状态
* 脱敏错误

MCP Server 只包装相同 registry，不复制业务逻辑。

更新随安装包分发的 Agent Skill 和命令参考。

# 十九、内置 Agent 自调试

保留并增强本机 Agent 自动化能力，让 Codex、Claude Code 等可以调试 SparkAI WorkSpace。

提供受控开发命令：

```text
debug.runtime-state
debug.renderer-logs
debug.main-logs
debug.run-targeted-test
debug.capture-window
debug.inspect-ipc
debug.inspect-command
```

生产安装包默认不允许任意写代码或执行系统命令。

开发模式可以允许受控调试，但必须：

* 限定仓库根目录
* 隐藏密钥和 Cookie
* 展示 diff
* 保存修改前 checkpoint
* 删除文件需要确认
* 只运行白名单命令
* 不允许 Agent 修改用户项目资产来伪造测试成功

# 二十、性能要求

性能和实际功能优先。

必须做到：

* 切换模式不重新挂载画布
* 插件面板按需动态加载
* 社媒和科研复杂对话框自然异步加载
* 不在应用启动时加载全部模板
* 不在模式切换时联网
* 不在设置分区切换时联网
* 不扫描全部项目资产
* 不复制大视频
* 不把数据集内容塞入普通 React state
* 不把完整 CSV 内容持续放入 Agent Prompt
* 对数据只提供摘要、字段和受限样本
* 大任务显示进度并允许取消
* 视频和科研执行不阻塞 Renderer
* 导出使用流式或文件复制，不使用大型 Base64

不要因为方便而把所有功能继续堆入 `src/main.tsx` 或 `electron-main.cjs`。

新逻辑应放入明确 owner 模块。

# 二十四、完成标准

只有以下条件全部满足，才算本次功能实现完成：

1. 用户可以在同一画布中自由切换四种模式。
2. 切换模式不会丢失画布、选择、任务和项目数据。
3. 电商模式正确复用已有 Commerce 系统。
4. 小红书工作流能完成 Brief、标题、正文、卡片和导出。
5. 抖音工作流能完成脚本、分镜、视频任务和发布包。
6. 社媒首次使用能由 `ask_user` 简短引导。
7. 科研模式能完成至少一个真实 Python 数据图表流程。
8. 环境可用时支持 R 绘图流程。
9. 多 Panel 结果可以在画布组织和导出。
10. 科研流程不虚构实验结果。
11. GUI、CLI、MCP 使用同一生产动作。
12. 旧项目可以正常打开、保存和继续编辑。
13. 没有新增 Renderer 凭据泄露。
14. 普通迭代只运行了针对性测试。
15. 全量测试仅留给最终发布阶段。

开始实施后，不要只汇报计划。

先检查代码和工作树状态，逐阶段完成实际修改。

每个阶段完成后输出：

* 修改内容
* 关键文件
* 实际运行的针对性测试
* 测试结果
* 尚未完成内容
* 性能或兼容风险

除非遇到无法从仓库和上下文解决的阻断问题，否则不要反复向用户请求确认。
