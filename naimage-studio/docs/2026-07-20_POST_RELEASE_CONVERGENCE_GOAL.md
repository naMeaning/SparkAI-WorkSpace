# IIIMAGE Studio 1.0.4 发布后收敛 Goal

更新时间：2026-07-20

状态：正式发布完成

## 目标

在 1.0.3 已完成生产发布的基础上，将产品继续收敛为更容易理解、更少重复状态、更少相似实现、能够可靠在线更新的阶段性交付版本。所有改动优先改善用户完成任务的速度和确定性，不以增加步骤或系统强制策略换取表面稳定。

## 本轮统一原则

1. Agent 仍是唯一智能主体；画布只提供明确的原图、参考图、需求、执行和成果关系。
2. 同类能力落到同一底层：图片容器、任务执行、忙碌状态、按钮、弹窗、状态提示和更新流程不得各自复制一套。
3. 一个执行只保留一个动态主状态；画布和节点使用静态占位与结果，不重复刷“生成中”。
4. 小更新优先下载签名 ASAR、重启、原子替换、健康检查与失败回滚；只有 Electron 壳、原生依赖、安装器或兼容协议变化才下载完整安装包。
5. 设置抽屉可以随时关闭；重新打开或应用重启后必须恢复真实更新进度和已下载状态。

## 更新状态闭环

| 状态 | 用户入口 | 必须表现 |
| --- | --- | --- |
| 未检查 | 检查更新 | 不自动制造紧迫提示 |
| 已是最新 | 重新检查 | 显示当前版本和最后结果 |
| 小更新可用 | 下载更新 | 后台下载，用户可继续工作 |
| 下载中 | 查看进度 | 关闭设置后继续；重开恢复进度 |
| 小更新已就绪 | 重启并更新 | 不要求重新检查；重启后原子替换 |
| 大版本可用 | 验证并下载 | 验证码只保护完整安装包下载 |
| 安装包已就绪 | 安装新版本 | 返回成功前确认安装器已启动 |
| 更新失败 | 重试 | 保留当前可用版本和可行动错误 |
| 自动回滚 | 重新检查 / 完整安装 | 明确告知已恢复，不静默掩盖失败 |

## 执行批次

### Round 1：更新可靠性

- 主进程保留最后一条更新进度并由 `status()` 恢复。
- pending 更新本身即为“已就绪”，不依赖刚刚完成过一次网络检查。
- 回滚状态进入设置 UI，并给出重新检查或完整安装建议。
- 完整安装器只有在 shutdown 与 spawn 成功后才向 Renderer 返回成功。
- 扩充更新自测、helper 与重启 E2E 的失败路径。

### Round 2：UI 基础设施

- 统一按钮尺寸、间距、footer、notice、表单和弹窗操作区。
- 节点控制界面只使用共享 primitive；处理窄宽、紧凑高度、滚动与 resize 冲突。
- 设置更新卡将版本、进度、动作和错误分层显示，不堆叠技术说明。

### Round 3：任务链路

- Renderer 和运行时使用同一个 Agent 忙碌能力定义。
- 聊天、需求、节点工具、编辑器与画布菜单共享防重入边界。
- AskUser 是暂停中的同一任务，不被当成空闲新任务；查看、整理和导出仍可使用。
- 执行、占位、结果和失败恢复继续使用统一 TaskExecution 协议。

### Round 4：AIDebug 与真实验证

- 设置更新抽屉关闭/重开恢复状态。
- pending 小更新在无网络检查时可直接重启安装。
- 回滚提示、安装器启动失败和下载失败具有可行动 UI。
- 884、1280、1536 宽度和紧凑高度下无按钮重叠、内容不可达或滚动冲突。
- 执行入口压力点击只接纳一个任务，AskUser 期间不可启动第二个任务。

### Round 5：阶段性交付

- 运行最小专项、一次代表性 GUI、typecheck、build、bundle 与 diff 检查。
- 审查相邻功能和持久化，不重复跑已经稳定的性能轮次。
- 所有门禁通过后再决定版本号、制品构建与服务器发布；不得把本地构建等同于发布。

## 完成标准

- 用户不需要理解 ASAR、兼容协议或回滚脚本，也能完成检查、下载、重启或安装。
- 设置关闭和应用重启不会丢失更新进度或已下载更新。
- 更新失败不会破坏当前版本，错误信息给出下一步。
- UI 基础组件在主要弹窗、节点控制与设置中一致。
- 任意任务入口不会在 Agent 忙碌或 AskUser 暂停期间重复接纳工作。
- 专项测试与 AIDebug 证据能够证明上述闭环，代码结构没有新增重复体系。

### 发布边界审计

- 发现 1.0.2 与 1.0.3 的外置 `image-import-worker.cjs` 已变化，但两版兼容标识相同；仅替换 `app.asar` 的用户不会获得新版 worker，在线升级与全新安装会形成运行时差异。
- 本轮又修改了外置 `update-helper.ps1`，因此首个包含本轮改动的版本必须完整安装一次。兼容标识已提升为 `windows-x64-electron-42-runtime-3`。
- 新增发布运行时指纹门禁：Electron 壳、extraResources、`app.asar.unpacked` worker 或原生依赖发生变化而未提升兼容标识时，正式发布会直接失败。
- 发现正式包携带 `ag-psd/.v8-cache` 共 2,516 个、约 9.1 MB 的无效缓存；已增加构建排除规则和 packaged smoke 污染门禁，下一次打包必须证明这些文件不再进入制品。
