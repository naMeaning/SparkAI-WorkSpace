# naimage 产品意图

更新时间：2026-07-16

## 我们最终想做什么

naimage 是面向普通用户和创作者的傻瓜式桌面 AI 生图工作台。它不是工作流编辑器、通用 Agent IDE 或 ComfyUI 复刻。右侧项目 Agent 是唯一控制中心，负责理解目标并生成或修改图片；它可以折叠为窄侧栏，但不会被卸载、变成画布节点或创建子 Agent。无限画布主要展示图片成果、图片分组和来源关系，并只允许一种可执行的非图片原语：可复用需求节点。

用户不在画布上创建 Agent、计划、Prompt 步骤、工具步骤或任意流程节点。用户既可选择成果继续对话，也可从图片/容器/分层成果创建一个需求节点，保存并持续优化某个自然语言处理要求。需求节点必须形成“来源 → 需求 → 成果”的单一结构；断开旧来源、接入新来源后可再次执行。同一来源和同一需求重复执行前需要确认。连线只表达来源关系，连线动作本身不执行任务。

每个项目拥有一个项目级 Agent、多个可切换的历史会话和一块单一成果画布。新建会话只重置当前对话上下文，不创建新 Agent，不产生子 Agent，也不清空项目成果。

`image_gen` 是唯一图片执行工具，覆盖七种任务语义：

- `generate`：文字生图；存在附件时自动作为参考图生图。
- `edit`：基于参考图或当前选中图片继续设计。
- `replace`：替换当前图片中的元素，原图保留，新结果作为衍生版本。
- `variants`：基于当前图片生成多种独立款式，禁止把多款拼成一张图。
- `layers`：生成合成预览、2-8 个同尺寸独立 PNG 图层和一张本地重组校验图；背景层不透明，其他层优先透明。
- `cutout`：先由用户涂抹要保留的主体大致区域并填写描述，再基于当前图片提取主体，经客户端 alpha 验证后保存真正透明 PNG；点击入口不得直接生成。
- `redraw`：基于当前图片和用户涂抹蒙版执行 AI 重绘；没有蒙版时先打开涂抹界面，不能假装已完成。

主 Agent 保留与 Codex 对齐的 `shell_command`、`view_image`、Responses 原生 `web_search`，以及 naimage 的 `experience`、记忆与 compact 等完成复杂任务所需的通用能力，也可读取和维护成果关系。`web_search` 不得被包装成自建搜索 function；`view_image` 通过 `function_call_output` 返回 `input_image`，由同一个主模型直接观察。`detail=high` 使用受控尺寸和请求体的模型观察副本，`detail=original` 保留原分辨率；任何观察副本都不能替换项目原图或降低画布显示清晰度。`context_manage` 与底层 memory 属于内部维护能力，不作为主 Agent 的普通公开工具。这些能力通过对话与时间线工作，不能变成画布节点、手动工作流或用户必须理解的执行步骤。

没有成果节点被选中时，画布只是空白工作区状态，不显示“当前选中/将基于画布”，也不向 Agent 传递画布选择上下文。

## 当前有效目标

- 启动后必须经过服务端登录或注册；登录后才能进入工作台。
- 客户端只展示账户、余额、使用日志和可选模型，不展示上游 URL、Key 或 relay token。
- 模型列表必须真实从服务端完整拉取，用户可自由选择对话模型和生图模型；不得在高层偷偷限制为固定模型。获取结果由主进程缓存至少 60 秒，设置页打开时先展示已有选择并自动读缓存，缓存有效期内不得重复请求服务器；缓存策略属于内部实现，不得在用户界面展示。用户连续第 6 次手动获取模型时必须绕过缓存真实刷新，随后重新计数。
- 无限画布保持流动、深邃、低成本的氛围背景，不使用明显网格，也不能用高开销粒子拖慢交互。
- 项目 Agent 始终存在，可折叠、停靠在上/下/左/右、应用内浮动，或打开为可移出主应用的独立 Electron 窗口。主 Renderer 是 Agent、画布、会话和项目状态唯一权威；独立窗只呈现脱敏有界快照并回传用户命令，不能创建第二个 Agent Runtime、重复模型请求或独立写项目。全部表面支持停止执行、清理聊天、会话历史、新建会话、当前成果上下文和当前会话 FastMemory 编辑；主面板继续支持 Markdown 和真实工具时间线。设置页提供主 Agent 纯文本 Prompt 编辑/恢复默认入口；Prompt、公开工具 Schema、conversation compact summary 与 FastMemory 必须独立存储和注入，Prompt 不再使用 entries 结构。清理聊天必须经确认，只清当前会话消息、summary 和该 `projectId + conversationId` 下的 FastMemory，不删除画布和其他会话。
- 新建会话必须获得全新 conversation ID、空消息和空 FastMemory 上下文，但继续共享当前项目画布；新建项目必须获得空画布、全新会话和独立 FastMemory，不能继承旧项目或旧会话上下文。
- Agent 输入区不提供“生成图片、分层 PNG、替换元素、多款设计”等系统强制快捷任务；一切任务由用户自然语言交给 Agent 自主理解并选择工具。参考图通过同一输入区添加或拖入聊天区域，拖入后只更新参考图容器计数，不额外铺设缩略图区域。
- 工具时间线显示模型提供的简短正文和无标题 Brief；流式正文结束事件不得再次追加同文案。Brief 位于工具卡边框之外，同一 tool call 的 start/poll/request 更新同一条“正在使用工具”卡片，done/error 必须另起一条独立的“工具完成/失败”结果卡片，过程与结果不能挤在一起。Experience 只显示“记录经验成功”等用户文案，禁止显示 `fmem-*` 或内部 entry id。Image Gen 的执行卡把单个或多个完整 Prompt 分别放入默认折叠块。
- 动态工作状态只能由右侧 Agent 时间线承担。Image Gen 执行期间，时间线保留唯一的“Image Gen 正在绘图 Ns”主状态；画布节点只显示静态类型、数量和无动画占位，不再重复“生图中 / 生成中 / 正在生成 / 运行中”或琥珀工作边框。画布底栏分别显示图片成果数量与可复用需求数量；失败、部分失败和停止等终态仍可在对应成果上明确显示。
- 画布不得出现 Agent 核心节点、节点内对话框、计划节点、工具调用节点、Prompt 节点或后期节点；唯一例外是可复用需求节点。空白画布右键保留“创建生图工作 / 导入图片 / 创建图片容器”：其中“创建生图工作”是直接提交到现有图片链路的精简表单，只收集 Prompt、比例、分辨率、质量、数量和参考图，不创建需求或工作流节点。图片成果和需求节点允许使用关系连接头手动调整“来源 → 需求 → 成果”，但连线动作不执行任务。
- 画布只保存图片成果和合法 v1 需求节点；其他旧非图片节点迁移时删除，无图片类型但包含有效图片资产的旧成果迁移为图片成果。
- 画布图片可以拖动、查看、编辑和删除；每张成果图在画布、图片容器、查看器、编辑器和分层查看器中都必须具备“另存为”入口。不提供 Windows 系统拖出把手，避免与画布内移动、归组和查看图片的手势冲突；大图查看器的主画面保留左键平移。分层节点遵循下方专用限制。右键空白画布可直接创建生图请求、导入图片或创建图片容器。外部单图、多图或文件夹拖入画布时先复制到项目图片库，再进入同一可视容器；容器内部使用小图网格，图片可拖出成为独立成果。
- 图片内容拖到另一张标准图片时，目标自动升级为可视图片容器并收纳两张图；容器关系只写入 `layoutGroups`，所有原始成果节点、`parentId` 和 `relationType` 必须保持不变。跨容器移动只改变布局成员顺序；容器剩一张时自动解组为标准单图，剩余图片稳定继承原容器位置。拖动标题或节点外框只移动节点，不触发归组。
- 单击图片内容打开查看器；双击图片内容或标题、以及右键“编辑成果”打开统一节点编辑器。编辑器支持修改标题、原始 Prompt/成果说明，并基于图片成果填写要求继续生图，继续结果必须是新节点，不能覆盖原图。
- 节点选择使用 `none / single / multiple` 统一状态：单选 A 后普通单击 B 必须切换为 B；Ctrl/Meta 单击负责增加或移除节点；中键拖框直接以框内节点替换当前选择，框内包含原单选时自然把它纳入多选；已有多选时普通单击任意单节点不得破坏集合，避免误触。普通空白画布点击或左键平移也不得清空选择；有效空框保持原选择。当前选中区域的 X、删除、清理/切换会话或项目等明确动作可以取消选择。所有选中节点必须保持可见高亮，Agent 当前成果上下文必须与选择集合一致。
- 图片或文件夹拖入聊天区域、输入框时直接加入现有参考图容器，不额外渲染缩略图条；单次参考图容量为 9 张，Agent 和生图运行时只使用项目库内统一路径。
- 多图请求必须返回多张独立图片；多款结果使用 `variant` 关系，元素替换使用 `derived-from`，分层素材使用 `grouped`。
- 图片任务默认使用 `gpt-image-2`；模型池存在 Image 2 时，编辑、抠图、透明 PNG 和 AI 重绘不得回退到旧图片模型。Agent 默认目标模型为最新 `gpt-5.6-sol`，同时保留服务端完整模型列表供配置和兼容。
- 参考图编辑上传只处理内存副本：当 PNG 过大时可转为较小 JPEG 上传，遇到 HTTP 413 时允许再压缩重试一次；用户原图和项目内原始成果不得被覆盖。
- 工具选择必须使用 `tool_choice=auto` 并依靠主 Agent Prompt、公开 schema、当前画布与会话上下文自主决定。系统不得用隐藏的关键词路由、首轮强制 tool choice 或前端规则替模型执行；如果模型不能正确调用，应修 Prompt/schema/上下文，而不是伪造 tool call 或补造画布成果。
- 单图使用标准图片节点；连续多图使用紧凑顺序系列；2-10 张并行结果与手动图片容器共用同一自适应底层。2 张双列；3 张先读取真实宽高比，同类比例使用横向三等分比较行，只有真正的横图离群项才置于上方主位、真正的竖图离群项才置于左侧主位；4 张为 2×2，5-6 张为 3×2，7-8 张为 4×2，9 张为 3×3，10 张为 5×2。4-10 张混合比例时按真实比例把相近方向归入同一比较行，并按该行代表比例自适应行高，减少横竖图混排的伪留白；这些调整只影响视觉呈现，不改变资产身份、Prompt 或索引。自动容器随图片数量和比例适配尺寸，用户手动缩放后停止自动改尺寸；不透明图片使用纯净底色，避免透明棋盘格造成伪留白。单图可从组中拖出并保留 Prompt 与 `grouped` 来源关系。
- `image_gen.items` 中仅为 `temp`、`placeholder`、`todo` 等占位语义的条目必须在工具执行前移除，不能产生请求、图片、标题或画布节点；过滤后只剩一个有效条目时必须降级为标准单图。
- 成果连线沿用旧版无箭头曲线与可拖拽连接头，禁止重复边和循环关系；线路使用稳定单段 Bézier，不做节点避障。节点按持久 `zOrder` 分层，线路保持在成果节点下方，同源多条边仅使用稳定 lane 轻微分岔，不随节点坐标重新排序。
- 分层 PNG 必须由同一组编号下的多个真实透明 PNG 节点在同一锚点叠放成图，而不是把全部图层塞进一个节点。任一层可在分层组内独立展开、显隐、查看和右键另存；右键“图层重组”按组编号、连续层序和原锚点恢复。图层节点不得加入普通图片容器；合并为新的普通图片成果后才恢复普通归组规则，且原图层组必须保留。专用查看器提供合成、单层、透视三种模式；分层组支持导出当前合成 PNG、包含全部独立图层与清单的文件夹，以及保留图层名称、顺序、显隐、透明度和画布尺寸的 Photoshop PSD。导出临时源必须按进程隔离、在完成后释放并安全清理崩溃残留，多个应用实例不得互删正在使用的文件。
- 滤镜、本地后期和 `apply_post_effect` 已彻底废弃；工具 schema、Agent 自动路由、前端 action、画布节点、菜单、CSS 和专项测试都不得恢复。
- 项目、成果、成果关系、会话和历史图片必须可靠绑定并持久化；重启后不得把旧缓存塞入无关成果。
- 旧项目中的 Agent 节点加载后必须移除，其历史会话保留为项目会话；`agentOwnerId` 不再参与运行时或绘图。
- 桌面 UI 采用紧凑 IDE 密度，固定最小工作宽度；抽屉、弹窗、节点和文字不能重叠、裁切或在窄窗口变成另一套混乱布局。
- AIDebug 必须跟随当前独立仓库和当前 UI，验证真实 DOM、截图、溢出、最小尺寸和关键链路，不能只因元素存在就判定通过。

## 已被后续请求覆盖或废弃的方向

- 不再把旧 `naimageServer` 本地管理后台打包进客户端；当前服务端属于独立后端仓库和远端部署。
- 不再保留“基础模式 / Agent 模式”切换；当前是统一的人机协同画布。
- 旧 Agent 实现曾被明确要求砍掉重做。只可复用可靠的布局、时间线和工具基础，不可原样恢复旧 Prompt、旧 Memory 或旧上下文拼接。
- 旧版本不是兼容目标或回归基线。只有用户明确认可的连接点、无箭头线路动画、窗口结构等局部设计可以迁移并适配新版；不得因为旧版全量测试失败而回退新版 Agent、画布、会话隔离或工具时间线。
- 2026-07-10 早期提出的“画布 Agent 核心节点 + 手动生图工作 + Agent 归属连线”方向已被后续产品判断废弃。不得恢复 Agent 节点、所属 Agent 连线或节点内会话。
- 旧本地智能抠图算法、旧滤镜入口、旧区域重绘入口和旧工作流侧栏曾被明确要求移除。后续只保留基于 `gpt-image-2`、必须先选区和描述的“AI 抠图”，以及带真实蒙版的“AI 重绘”；不得恢复点击即抠图、旧本地算法、滤镜或旧工作流入口。
- 旧“创建生图任务”工作流弹窗、复杂风格向导、Prompt/后期节点和 Agent 可见的画布管理工具均已被最新极简方向覆盖，不得恢复。当前空白画布的精简“创建生图工作”仅是次级直接提交入口，不属于旧工作流。
- 不要重新加入启动即弹出的“创建生图工作”提示卡，也不要恢复画布网格。
- 不要把配置、项目列表或运行时数据写到仓库外的随机目录；独立仓库的诊断和配置应留在本项目内。
- 2026-07-09 曾提出“母 Agent 创建、列出、管理子 Agent”，该方向已被 2026-07-10 的后续请求覆盖。不得恢复 `create_agent_node`、`list_agents`、`manage_agent` 或相关 Prompt。

## 质量标准

简洁、直观、规范、稳定、新手友好；动效服务于反馈和流畅感，不用于炫技。实现应优先修正底层参数和数据链路，避免通过层层 CSS 覆盖或临时状态补丁制造新的残留。每轮功能变更至少完成构建、AIDebug GUI 基线和对应的真实链路验证。
