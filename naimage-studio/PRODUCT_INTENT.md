# SparkAI WorkSpace 产品意图

更新时间：2026-08-04

## 我们最终想做什么

SparkAI WorkSpace 是面向普通用户和创作者的傻瓜式桌面 AI 图片、视频与专业视觉成果工作台。它在同一个项目、同一张无限画布和同一个项目 Agent 中提供通用创作、电商创作、社媒创作与科研绘图四种可切换工作台；领域切换只改变入口、插件、推荐流程与简短 Agent 上下文，不复制项目状态、画布、Session、资产、TaskScope、Requirement、provenance、Agent Runtime 或 CLI/MCP 注册表。它不是工作流编辑器、通用 Agent IDE 或 ComfyUI 复刻。右侧项目 Agent 是唯一控制中心，负责理解目标并生成或修改成果；它可以折叠为窄侧栏，但不会被卸载、变成画布节点或创建子 Agent。无限画布主要展示图片成果、非执行型视频成果、图片分组和来源关系，并只允许一种可执行的非图片原语：可复用需求节点。用户导入的单文件 `SKILL.md` 作为带 `CanvasSkill` 身份的可复用需求呈现和持久化，仍沿用需求节点的来源关系、TaskScope 与执行入口，不扩张为任意工作流节点。

用户不在画布上创建 Agent、计划、Prompt 步骤、工具步骤或任意流程节点。用户既可选择成果继续对话，也可从图片/容器/分层成果创建一个需求节点，保存并持续优化某个自然语言处理要求。需求节点必须形成“来源 → 需求 → 成果”的单一结构；断开旧来源、接入新来源后可再次执行。同一来源和同一需求重复执行前需要确认。连线只表达来源关系，连线动作本身不执行任务。

每个项目拥有一个项目级 Agent、多个可切换的历史会话和一块单一成果画布。新建会话只重置当前对话上下文，不创建新 Agent，不产生子 Agent，也不清空项目成果。

`image_gen` 是唯一图片执行工具，覆盖七种任务语义：

- `generate`：文字生图；存在附件时自动作为参考图生图。
- `edit`：基于参考图或当前选中图片继续设计。
- `replace`：替换当前图片中的元素，原图保留，新结果作为衍生版本。
- `variants`：基于当前图片生成多种独立款式，禁止把多款拼成一张图。
- `layers`：生成合成预览、2-8 个同尺寸独立 PNG 图层和一张本地重组校验图；背景层不透明，其他层优先透明。
- `cutout`：先由用户涂抹要保留的主体大致区域并填写描述，再基于当前图片提取主体，经客户端 alpha 验证后保存真正透明 PNG；点击入口不得直接生成。
- `redraw`：基于当前图片和用户涂抹蒙版执行 AI 重绘；没有蒙版时先打开涂抹界面，不能假装已完成。

视频节点接受用户授权的本地 MP4、WebM、MOV 和 M4V：文件先复制到项目 `output/video` 受管目录，再以独立成果节点播放、保存尺寸/时长并在重启后恢复。`doubao-seedance-2-0-260128` 已进入视频模型目录、设置默认值及独立的 create/poll/download 任务链路；这条链路处于“已开发、未用真实 Token 验证”的状态，不代表兼容请求或计费边界已经固定。用户提供的 Chat Completions 示例不足以定义视频任务；未获得明确测试授权前不得发起真实 Seedance 请求，也不得在创建结果不明时自动重建。

主 Agent 保留与 Codex 对齐的 `shell_command`、`view_image`、Responses 原生 `web_search`，以及 SparkAI WorkSpace 的 `experience`、记忆与 compact 等完成复杂任务所需的通用能力，也可读取和维护成果关系。`web_search` 不得被包装成自建搜索 function；`view_image` 通过 `function_call_output` 返回 `input_image`，由同一个主模型直接观察。`detail=high` 使用受控尺寸和请求体的模型观察副本，`detail=original` 保留原分辨率；任何观察副本都不能替换项目原图或降低画布显示清晰度。`context_manage` 与底层 memory 属于内部维护能力，不作为主 Agent 的普通公开工具。这些能力通过对话与时间线工作，不能变成画布节点、手动工作流或用户必须理解的执行步骤。

没有成果节点被选中时，画布只是空白工作区状态，不显示“当前选中/将基于画布”，也不向 Agent 传递画布选择上下文。

## 当前有效目标

- 每个项目持久化 `workspaceDomain`；旧项目缺失或字段无效时使用 `general`。顶部紧凑切换器、`Ctrl/Cmd + 1–4` 和新项目四入口共用统一领域注册表；在支持的最小窗口中仍必须显示当前工作台文字，不能退化为含义不明的单图标。切换不得重挂 canonical 画布、丢失选择/任务/关系、清空对话、调用模型或产生费用；主/独立 Agent 快照、自动化状态与 Agent 领域提示必须读取同一项目状态。
- 四模式基础、电商领域投影、`sparkai.social-content` 社媒工作台和 `sparkai.scientific-figure` 科研工作台已实现；电商、社媒和科研三个第一方工作台组件在版本化首次迁移时默认安装并启用，之后必须尊重用户的停用或卸载选择。`general` 保留所有已启用工具，其他模式只投影自身或未归属的全局插件。`commerce` 的底部工具栏与左素材轨快捷区复用同一组 Commerce 命令；组件被用户停用或卸载时才引导进入相关设置，不擅自覆盖其选择。社媒模式已提供小红书与抖音结构化计划、Requirement/provenance、首次引导、现有视频任务接入、原生发布包和共享 CLI 命令。科研模式已提供受管 CSV/TSV/TXT 数据、结构化 Requirement、单 Python/R 后端安全 Runner、Panel/组合图、投稿格式导出与 7 个共享 CLI 命令；Python 路径已经专项验证，R 路径尚未在真实 R 环境验证。真实图片模型与 Seedance 付费生成仍未验证。
- 设置中的逐工具复选框只决定底部工具栏与素材轨领域菜单是否展示。隐藏工具后，快捷键、Agent 和 CLI 仍可调用同一插件命令；只有插件本身停用或卸载才关闭能力，视觉偏好不得改变授权或自动化契约。
- 图片上游支持 partial image 时，画布在每个 `operationId + requestIndex` 请求槽位中最多显示一张当前预览，按 `1/3 → 2/3 → 3/3` 实时替换；最终图返回后由受管成果覆盖并清理临时状态。partial 不进入图片库、项目 Session、Agent 消息或独立窗口。用户主动执行生图即授权调用，上游计费由对应 Base URL/账号服务负责；桌面不以预估费用或完整费用元数据阻断，完成后收到 usage 时才可选记录。
- 普通 `parallel` 多图在配置并发上限内直接同批派发；任一请求完成后必须立即以同一 operation 更新画布上的同一个图片组，资产按实际完成顺序追加，不能等最后一张结束才整体显示。Goal 仍先 probe 再渐进放量，但每个母图只对应一个结果图片组，组内每张成果保留自身槽位、语言、SKU 和幂等 provenance。
- 帮助中心已提供首个基于真实画布状态的“跨境电商套图”AI 陪练。它引导用户导入/粘贴母图、选择图片、切换电商工作台，再选择套图工具或 Agent 示例话术；Agent 路径只填入输入框，不自动发送。教学自身零费用，仅用户亲自执行套图或发送 Agent 请求才可能扣费；只有检测到教学开始后新增的 Commerce 受管成果才判定成功。进度按项目保留，完成后提供低成本庆祝动效、徽章、专注查看与平台导出入口。
- GUI、CLI 与 MCP 由同一个 76 项 command schema 驱动；MCP 只把这些命令包装为 stdio tools 并转发 authenticated loopback bridge，不创建第二套业务实现。7 个 `debug.*` 命令只服务本地开发/AIDebug，输出有界脱敏、截图固定诊断目录、测试固定白名单且无任意 shell；生产安装包默认拒绝，调试能力不能修改用户项目资产、安装依赖或越过模型/计费授权。
- 启动后必须满足两种通行条件之一：成功登录 SparkAPI/New API 账号，或当前设备持有有效 Pro License 且已配置自定义 OpenAI-compatible Base URL/API Key。账号登录本身就是软件使用授权，不再要求设备兑换码；未登录且未完成 Pro 自定义接口配置时不能进入工作台。
- SparkAPI 保持为用户独立部署、可正常跟随上游升级的原生 New API，不在本项目复制或二次开发。`ai-native` 只部署轻量 SparkAI Extension：同域 `/api/naimage/license*` 管理 Pro 设备授权，`/v1/image-tasks*` 以调用者 Bearer Key 在内存中包装原生同步 Images API；账号、Token、渠道、quota、计费、用量与 Web 管理仍全部属于原生 New API。扩展 Worker 默认加入 New API 的 user-defined Docker network 并使用容器 DNS/内部端口，禁止重新经过 Cloudflare 公网；SQLite 不保存模型 Key，重启不重放未完成任务。
- Windows 发行分为 `dual-access` 与 `sparkapi-account` 两种构建期接入策略。前者允许 SparkAPI 账号登录和 Pro 授权后的用户自定义 OpenAI-compatible Base URL/API Key；后者固定 `https://sparkapi.org`、强制账号模式并由 Electron Main 拒绝全局自定义接口。策略写入构建产物，不使用运行 EXE 时可篡改的环境变量作为生产门禁；两种发行版继续共享同一产品数据和功能代码。
- 账号模式必须继续允许每个对话/图片模型单独填写自定义 API Key，优先级为“模型自定义 Key → 模型绑定账户 Token → 全局账户 Token”。账号模式不接受逐模型自定义 Base URL，模型 Key 始终请求账号/Relay 地址；逐模型 Key 继续只保存在 Windows `safeStorage` sidecar。SparkAPI 专用版禁止的是全局自定义 Base URL 模式，不得因此移除账号登录后的逐模型自定义 Key。
- 客户端只展示账户、余额、使用日志和可选模型，不展示上游 URL、Key 或 relay token。
- 模型列表必须能够从服务端完整拉取，用户可自由选择对话、生图和视频模型；不得在高层偷偷限制为固定模型。模型分类只影响可见选择，不得从服务端原始目录中静默丢弃模型。主进程分别持久化脱敏的账户密钥快照和模型/分组快照；设置页打开时只读本地快照或已有选择，不得自动访问服务器。用户点击“刷新密钥与分组”或“刷新模型”时单击即真实刷新并更新快照，不使用隐藏的多击门槛。界面可以显示简洁的快照更新时间，但不得展示完整 Key、Cookie、底层缓存路径或其他敏感实现细节。
- 无限画布保持流动、深邃、低成本的氛围背景，不使用明显网格，也不能用高开销粒子拖慢交互。
- 透明玻璃是全产品统一材质语言，不只用于顶栏和弹窗：图片容器、成果/Requirement/科研 Panel 节点的外壳、标题区和控件也应复用现有 Glass token、圆角、描边、阴影与层次。内置七套主题共用同一 registry，新装默认“蜜橘融光” (`dark-ember + frosted`)，并提供安装程序风格的“雾银玻璃” (`light-silver`)。图片和视频作品内容本身必须保持不透明、原色、无 `filter`/`backdrop-filter`，文字与菜单保持足够对比；不得为了更强玻璃效果引入明显滚动、拖动画布或首帧性能退化。
- 项目 Agent 始终存在，可折叠、停靠在上/下/左/右、应用内浮动，或打开为可移出主应用的独立 Electron 窗口。主 Renderer 是 Agent、画布、会话和项目状态唯一权威；独立窗只呈现脱敏有界快照并回传用户命令，不能创建第二个 Agent Runtime、重复模型请求或独立写项目。每个主 Renderer 是自己运行和 automation pending 的明确 owner：窗口关闭/崩溃必须停止它尚未完成的运行、立即拒绝其 CLI 等待且不影响其他窗口；应用退出必须先停止全部 run，再拆 transport，在途 provider 请求仍需排空。停止操作在 Main 返回权威 `ok: true` 前必须保持原运行态并显示“正在结束”，重复停止不得发出第二次 IPC；bridge 缺失、拒绝或畸形响应必须保留可重试状态，不能让 Renderer 假装进入 idle。全部表面支持停止执行、清理聊天、会话历史、新建会话、当前成果上下文和当前会话 FastMemory 编辑；主面板继续支持 Markdown 和真实工具时间线。设置页提供主 Agent 纯文本 Prompt 编辑/恢复默认入口；Prompt、公开工具 Schema、conversation compact summary 与 FastMemory 必须独立存储和注入，Prompt 不再使用 entries 结构。清理聊天必须经确认，只清当前会话消息、summary 和该 `projectId + conversationId` 下的 FastMemory，不删除画布和其他会话。
- 新建会话必须获得全新 conversation ID、空消息和空 FastMemory 上下文，但继续共享当前项目画布；新建项目必须获得空画布、全新会话和独立 FastMemory，不能继承旧项目或旧会话上下文。
- Agent 输入区不提供“生成图片、分层 PNG、替换元素、多款设计”等系统强制快捷任务；一切任务由用户自然语言交给 Agent 自主理解并选择工具。原图与参考图动作统一收进“素材”菜单，参考图仍可拖入聊天区域；输入区以紧凑玻璃工具栏呈现模型、素材、模式、比例值和清晰度值，不重复显示“比例 / 清晰度”长标签，也不额外铺设缩略图区域。
- Agent 输入区提供互斥的“普通 / Goal”模式，但只显示一个当前模式按钮；悬停、聚焦或点击后展开双瓣玻璃扇形供用户切换，不常驻两组相邻按钮。Goal 表示把同一自然语言要求应用到当前画布全部合格图片容器：系统先排除纯参考、空和生成中的容器，按每个图片槽位冻结有序 binding、容器/图片计数、并发策略和 TaskScope hash，向用户展示范围与费用警告；只有用户明确确认且派发前 hash 仍一致才可执行。主窗口、独立 Agent 窗口与 `agent.goal` CLI 必须使用同一两阶段预览/确认协议，画布或 Prompt 改变后不得复用旧确认。
- Goal 高并发必须先小批量验证：从 1–2 个不同容器各选一张代表图串行 probe，只有请求成功、结果落盘、完整解码、非零尺寸和交付画幅全部通过，才按 `2 → 4 → 用户配置上限` 放量。所有 Renderer 共享 Main 进程准入：等待 probe 时停止批准新 ramp，已通过的 Goal 公平共享冻结容量；限流、5xx 或网络重试期间暂停新波次，保护性或集中失败打开跨 Goal circuit。同一项目同时只允许一个已确认 Goal；窗口退出或 Abort 后，已启动请求仍占用额度直到真实 provider Promise 收尾。保护只能阻止未派发请求，已经被上游接受的请求仍可能计费，界面与 CLI 不得承诺取消后免单。
- Goal v1 只允许 `edit`、`replace`、`variants`；每个冻结 binding 按用户确认的 `operationsPerAsset` 产生一个或多个独立成果并保留各自来源与 provenance，总请求不超过 200。模型对整个 Goal 只调用一次图片工具，由 runtime 展开全部 SOURCE；跨境电商多项计划必须提供与确认槽位/语言顺序等长的 `items`。首批不支持额外 REFERENCE、layers、cutout、redraw 或运行中改变 SOURCE/REFERENCE；运行中修改只接受文本 steer，范围变化必须重新预览并确认。
- 工具时间线显示模型提供的简短正文和无标题 Brief；流式正文结束事件不得再次追加同文案。Brief 位于工具卡边框之外，同一 tool call 的 start/poll/request 更新同一条“正在使用工具”卡片，done/error 必须另起一条独立的“工具完成/失败”结果卡片，过程与结果不能挤在一起。Experience 只显示“记录经验成功”等用户文案，禁止显示 `fmem-*` 或内部 entry id。Image Gen 的执行卡把单个或多个完整 Prompt 分别放入默认折叠块。
- 动态工作状态只能由右侧 Agent 时间线承担。Image Gen 执行期间，时间线保留唯一的“Image Gen 正在绘图 Ns”主状态；画布节点只显示静态类型、数量和无动画占位，不再重复“生图中 / 生成中 / 正在生成 / 运行中”或琥珀工作边框。画布底栏分别显示图片成果、视频成果与可复用需求数量；失败、部分失败和停止等终态仍可在对应成果上明确显示。
- 画布不得出现 Agent 核心节点、节点内对话框、计划节点、工具调用节点、Prompt 节点或后期节点；可复用需求节点是唯一可执行的非图片例外，视频成果节点始终不可执行。空白画布右键保留“创建生图工作 / 创建视频工作 / 导入图片 / 导入视频 / 创建图片容器”等入口：其中“创建生图工作”直接提交到现有图片链路；“创建视频工作”每次只提交一个独立视频任务并创建结果占位，任务由 Main journal 恢复，结果节点不执行模型；“导入视频”只复制本地文件并创建成果节点。图片成果和需求节点允许使用关系连接头手动调整“来源 → 需求 → 成果”，但连线动作不执行任务。
- 画布菜单可导入用户明确选择的单个 `SKILL.md`，CLI 使用 `canvas.import-skill` 走同一解析与创建逻辑。导入文件不超过 256 KiB，指令不超过需求文本可无损持久化的 24,000 字符；frontmatter 缺失、字段超限或正文为空必须明确拒绝，不得静默裁切。项目只保存名称、描述、文件标签、内容 fingerprint、导入时间和指令，不保存绝对源路径；首批不复制同级 `scripts/`、`references/`、`assets/`。
- 画布保存图片成果、合法视频成果和合法 v1 需求节点；其他旧非图片节点迁移时删除，无图片类型但包含有效图片资产的旧成果迁移为图片成果。视频会话只持久化受管相对路径，运行时绝对路径和 `naimage-asset:` URL 在重启恢复时重建。
- 画布图片可以拖动、查看、编辑和删除；每张成果图在画布、图片容器、查看器、编辑器和分层查看器中都必须具备“另存为”入口。不提供 Windows 系统拖出把手，避免与画布内移动、归组和查看图片的手势冲突；大图查看器的主画面保留左键平移。分层节点遵循下方专用限制。右键空白画布可直接创建生图请求、导入图片、导入视频或创建图片容器。外部单图、多图或文件夹拖入画布时先复制到项目图片库，再进入同一可视容器；容器内部使用小图网格，图片可拖出成为独立成果。外部视频按扩展名分流到项目视频库，每个文件创建一个独立可播放节点，不修改源文件。
- 当前 `.naimage` 便携项目包仍是有界图片 Base64 格式，含视频节点时必须明确拒绝导入/导出；迁移视频项目应复制完整项目文件夹，直到后续设计独立的流式视频打包格式。
- 图片内容拖到另一张标准图片时，目标自动升级为可视图片容器并收纳两张图；容器关系只写入 `layoutGroups`，所有原始成果节点、`parentId` 和 `relationType` 必须保持不变。跨容器移动只改变布局成员顺序；容器剩一张时自动解组为标准单图，剩余图片稳定继承原容器位置。拖动标题或节点外框只移动节点，不触发归组。
- 单击图片内容打开查看器；双击图片内容或标题、以及右键“编辑成果”打开统一节点编辑器。编辑器支持修改标题、原始 Prompt/成果说明，并基于图片成果填写要求继续生图，继续结果必须是新节点，不能覆盖原图。
- 节点选择使用 `none / single / multiple` 统一状态：单选 A 后普通单击 B 必须切换为 B；Ctrl/Meta 单击负责增加或移除节点；中键拖框直接以框内节点替换当前选择，框内包含原单选时自然把它纳入多选；已有多选时普通单击任意单节点不得破坏集合，避免误触。普通空白画布点击或左键平移也不得清空选择；有效空框保持原选择。当前选中区域的 X、删除、清理/切换会话或项目等明确动作可以取消选择。所有选中节点必须保持可见高亮，Agent 当前成果上下文必须与选择集合一致。
- 图片或文件夹拖入聊天区域、输入框时直接加入现有参考图容器，不额外渲染缩略图条；单次参考图容量为 9 张，Agent 和生图运行时只使用项目库内统一路径。
- 多图请求必须返回多张独立图片；多款结果使用 `variant` 关系，元素替换使用 `derived-from`，分层素材使用 `grouped`。
- 图片任务默认使用 `gpt-image-2`；模型池存在 Image 2 时，编辑、抠图、透明 PNG 和 AI 重绘不得回退到旧图片模型。Agent 新装默认目标模型为服务端目录中真实存在的 `gpt-5.6-terra`，同时保留服务端完整模型列表、原始 ID 与大小写供配置和兼容。
- 参考图编辑上传只处理内存副本：当 PNG 过大时可转为较小 JPEG 上传，遇到 HTTP 413 时允许再压缩重试一次；用户原图和项目内原始成果不得被覆盖。
- 生图 SOURCE/REFERENCE 输入与上游图片结果统一支持 PNG、JPEG、WebP，默认输出 PNG。单张成果可在本地另存为 PNG、JPEG、WebP、AVIF 或 TIFF，分层成果继续保留 Photoshop PSD；格式转换由 Electron Main 使用 Sharp 本地完成，不调用 Agent 或图片模型，也不消耗生图额度。JPEG 导出固定以白色背景展平透明像素。GUI 和 CLI `canvas.export-image` 必须共用原生 Save 对话框授权链路，只读取受管源图并写入用户选择的位置，不允许命令 JSON 指定任意目标路径，也不得覆盖或修改项目受管源资产。Provider 返回 URL 时，Main 必须先按逐跳公网 HTTP(S)、固定 DNS 与真实 socket 地址复核策略下载并落为受管文件；远程下载使用小型全局准入与同 URL 在途去重；Renderer 只能显示 `naimage-asset:`，不得直接请求远程图片 URL。
- 工具选择必须使用 `tool_choice=auto` 并依靠主 Agent Prompt、公开 schema、当前画布与会话上下文自主决定。系统不得用隐藏的关键词路由、首轮强制 tool choice 或前端规则替模型执行；如果模型不能正确调用，应修 Prompt/schema/上下文，而不是伪造 tool call 或补造画布成果。
- 单图使用标准图片节点；连续多图使用紧凑顺序系列；2-10 张并行结果与手动图片容器共用同一自适应底层。2 张双列；3 张先读取真实宽高比，同类比例使用横向三等分比较行，只有真正的横图离群项才置于上方主位、真正的竖图离群项才置于左侧主位；4 张为 2×2，5-6 张为 3×2，7-8 张为 4×2，9 张为 3×3，10 张为 5×2。4-10 张混合比例时按真实比例把相近方向归入同一比较行，并按该行代表比例自适应行高，减少横竖图混排的伪留白；这些调整只影响视觉呈现，不改变资产身份、Prompt 或索引。自动容器随图片数量和比例适配尺寸，用户手动缩放后停止自动改尺寸；不透明图片使用纯净底色，避免透明棋盘格造成伪留白。单图可从组中拖出并保留 Prompt 与 `grouped` 来源关系。
- `image_gen.items` 中仅为 `temp`、`placeholder`、`todo` 等占位语义的条目必须在工具执行前移除，不能产生请求、图片、标题或画布节点；过滤后只剩一个有效条目时必须降级为标准单图。
- 成果连线沿用旧版无箭头曲线与可拖拽连接头，禁止重复边和循环关系；线路使用稳定单段 Bézier，不做节点避障。节点按持久 `zOrder` 分层，线路保持在成果节点下方，同源多条边仅使用稳定 lane 轻微分岔，不随节点坐标重新排序。
- 分层 PNG 必须由同一组编号下的多个真实透明 PNG 节点在同一锚点叠放成图，而不是把全部图层塞进一个节点。任一层可在分层组内独立展开、显隐、查看和右键另存；右键“图层重组”按组编号、连续层序和原锚点恢复。图层节点不得加入普通图片容器；合并为新的普通图片成果后才恢复普通归组规则，且原图层组必须保留。专用查看器提供合成、单层、透视三种模式；分层组支持导出当前合成 PNG、包含全部独立图层与清单的文件夹，以及保留图层名称、顺序、显隐、透明度和画布尺寸的 Photoshop PSD。导出临时源必须按进程隔离、在完成后释放并安全清理崩溃残留，多个应用实例不得互删正在使用的文件。
- 滤镜、本地后期和 `apply_post_effect` 已彻底废弃；工具 schema、Agent 自动路由、前端 action、画布节点、菜单、CSS 和专项测试都不得恢复。
- 项目、成果、成果关系、会话和历史图片必须可靠绑定并持久化；重启后不得把旧缓存塞入无关成果。
- 旧项目中的 Agent 节点加载后必须移除，其历史会话保留为项目会话；`agentOwnerId` 不再参与运行时或绘图。
- 桌面 UI 采用紧凑 IDE 密度，固定最小工作宽度；抽屉、弹窗、节点和文字不能重叠、裁切或在窄窗口变成另一套混乱布局。
- AIDebug 必须跟随当前独立仓库和当前 UI，验证真实 DOM、截图、溢出、最小尺寸和关键链路，不能只因元素存在就判定通过。

## 质量标准

简洁、直观、规范、稳定、新手友好；动效服务于反馈和流畅感，不用于炫技。实现应优先修正底层参数和数据链路，避免通过层层 CSS 覆盖或临时状态补丁制造新的残留。每轮功能变更按影响范围运行最小专项验证；Renderer 变化至少完成构建与分层 bundle 检查。initial JS（685,000 B 目标 + 1,024 B 测量容差）、plugin JS 120,000 B 和 CSS 270,000 B 是硬门禁；core async JS 190,000 B、core JS 870,000 B 与完整 dist 1,200,000 B 是增量趋势 advisory。真实产品性能由 `aidebug:performance:product` 独立硬门禁负责；不得为旧 Bundle 数字牺牲可维护性或增加高风险拆分。只有真实可视交互风险需要时才追加对应 AIDebug 场景，不默认运行全量 GUI 门禁。
