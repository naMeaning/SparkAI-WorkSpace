# naimage automation commands

> Generated from `commands.schema.json`; do not edit this file directly.

Invoke commands with `scripts/naimage.ps1 <command> -ArgsJson '<json>'`.

## Status and inspection

- `status`. Check the local authenticated bridge and renderer readiness.
- `app.state`. Return active project, conversation, Agent status, active run ID, pause state, selection, viewport, node summaries, and recent messages.
- `canvas.state`: `{}`. Return the active project and local canvas revision, selection, canonical relations, Requirement input bindings and revision/signature, canonical container membership, presentation layout membership, and per-node lock/busy details. Managed asset paths and automation credentials are never returned.

## Projects

- `project.list`. List projects and the active project ID.
- `project.switch`: `{ "id": "project-id" }`. Switch to an existing project.
- `project.create`: `{ "name": "Project name" }`. Create and activate a project.
- `project.rename`: `{ "name": "New name" }`. Rename the active project.

## Canvas

- `canvas.select`: `{"ids":[]}`. Atomically replace the canvas selection. Every supplied node ID and primaryId must exist; a mixed valid/stale list fails without changing selection. Use an empty ids array to clear selection.
- `canvas.connect`: `{"edges":[{"sourceId":"sourceId","targetId":"targetId"}],"replaceExisting":false,"expectedProjectId":"expectedProjectId"}`. Atomically add one or more exact graph edges. Requirement targets accept multiple image inputs and persist inputRole as SOURCE or REFERENCE; ordinary targets keep one parent. Connections never execute a Requirement. Replacing an existing ordinary parent requires replaceExisting=true.
- `canvas.disconnect`: `{"edges":[{"sourceId":"sourceId","targetId":"targetId"}],"expectedProjectId":"expectedProjectId"}`. Atomically remove the exact listed graph edges. Requirement bindings and their primary compatibility parent are recomputed together. If any requested edge is stale or absent, no edge is removed.
- `canvas.group`: `{"nodeIds":["nodeIds-1","nodeIds-2"],"expectedProjectId":"expectedProjectId"}`. Atomically group an explicit set of compatible image results or containers into one canonical image container. Unsupported, empty, layer, stale, or locked members fail the whole command; no partial subset is grouped.
- `canvas.dissolve`: `{"containerIds":["containerIds-1"],"expectedProjectId":"expectedProjectId"}`. Atomically dissolve one or more exact visible image-container hosts, restore their members as independent canvas results, and preserve provenance relations. Any stale or locked container fails the whole command.
- `canvas.nudge`: `{"nodeIds":["nodeIds-1"],"dx":0,"dy":0,"expectedProjectId":"expectedProjectId"}`. Atomically move explicit nodes or visible container hosts by a relative integer offset. Group members are mapped to their host once and locked nodes fail the whole command.
- `canvas.create-requirement`: `{"text":"text","expectedProjectId":"expectedProjectId"}`. Create one reusable Requirement node with an optional explicit ordered SOURCE/REFERENCE input set. Creation never executes the Requirement and commits the node and all bindings together.
- `canvas.update-requirement`: `{"nodeId":"nodeId","expectedRevision":1,"patch":{"title":"title"},"expectedProjectId":"expectedProjectId"}`. Atomically update a Requirement title, instructions, or complete ordered input binding set. expectedRevision is a required compare-and-set guard. Editing imported Skill instructions preserves the import fingerprint as source identity and marks the Skill locally modified.
- `canvas.execute-requirement`: `{"nodeId":"REQ_A","expectedRequirementRevision":3,"expectedProjectId":"PROJECT_ID"}`. Validate and execute one current Requirement or Skill through the same frozen Requirement TaskScope path as the GUI, then wait for the current Agent turn to settle. A repeated unchanged run requires confirmedUnchanged=true; a busy Agent or stale revision fails before dispatch.
- `canvas.fit`. Fit current results into view.
- `canvas.clear`: `{ "mode": "failed | all", "confirmed": true }`. Clear failed results or, with explicit confirmation, the whole canvas.
- `canvas.delete-selected`: `{ "confirmed": true }`. Delete selected nodes after explicit user authorization.
- `canvas.create-container`: `{ "x": 180, "y": 160, "role": "source | reference" }`. Create an image container; omit role for a normal container.
- `canvas.import`: `{ "paths": ["C:\\path\\image.png"], "targetContainerId": "optional-node-id", "x": 240, "y": 180 }`. Copy local images into the active project and place them on the canvas.
- `canvas.import-skill`: `{ "markdown": "---\nname: product-photo\ndescription: Product photography guidance\n---\n\nFollow these instructions...", "sourceName": "SKILL.md", "x": 240, "y": 180 }`. Import one bounded SKILL.md document as a reusable Skill-backed requirement node. An unchanged exact re-import selects the existing node. If that node's instructions were edited locally, the response returns exact:false and conflict:locally-modified without overwriting local text.
- `canvas.export-image`: `{"nodeId":"nodeId","assetIndex":0,"format":"png"}`. Export one canvas image through the native Save dialog as PNG, JPEG, WebP, AVIF, or TIFF. Conversion is local, does not call an image model, and never overwrites the managed source asset. Recorded remote assets are accepted only through the app's public-HTTP(S), redirect-validated managed asset path.

## Requirement library

- `requirement-library.list`: `{"includeText":false}`. List the installation-local personal Requirement template library across projects. By default the response contains bounded summaries; includeText=true returns the complete stored instructions. Every library item still instantiates as a normal Requirement node, including items carrying Skill metadata.
- `requirement-library.save`: `{"nodeId":"REQ_A","expectedRequirementRevision":3,"expectedProjectId":"PROJECT_ID"}`. Save one current canvas Requirement into the installation-local personal template library. expectedRequirementRevision and expectedProjectId guard the source node. Omit templateId to create a new item; when overwriting, pass templateId and its exact expectedTemplateRevision. The complete operation validates before one local CAS write.
- `requirement-library.delete`: `{"templateId":"reqtpl-0123456789abcdef0123456789abcdef","expectedTemplateRevision":1,"confirmed":true}`. Delete one personal Requirement template only when its exact revision is still current and confirmed=true. This does not delete any Requirement nodes already instantiated on project canvases.
- `requirement-library.use`: `{"templateId":"reqtpl-0123456789abcdef0123456789abcdef","expectedTemplateRevision":1,"inputBindings":[{"nodeId":"IMAGE_A","role":"source"}],"expectedProjectId":"PROJECT_ID","expectedCanvasRevision":44}`. Instantiate one exact personal template revision on the active canvas as a normal Requirement node. Optional ordered SOURCE/REFERENCE bindings and position use the same graph validation and project/canvas compare-and-set guards as direct Requirement creation. This command never executes the Requirement, never calls an image model, and never spends image quota.

## Agent

- `agent.chat`: `{"prompt":"prompt","sourceNodeIds":[]}`. Start an idle task and wait for its current Agent turn to settle. While a task is already running, this command performs a text-only steer with the frozen TaskScope kept unchanged and returns after acceptance; sourceNodeIds are then rejected and explicit attachment changes must use agent.steer. Every supplied sourceNodeId must still exist; a mixed valid/stale list fails before any Agent call.
- `agent.goal`: `{"prompt":"prompt","sourceNodeIds":[],"operationsPerAsset":1,"confirmed":false}`. Preview or execute a Goal across either the exact sourceNodeIds or, when omitted, all eligible SOURCE image containers. operationsPerAsset freezes the number of requested operations for every eligible source asset. Empty, generating, stale, and reference-only containers are rejected or reported as skipped before dispatch. First omit confirmed (or use false) to receive requiresConfirmation, counts, and a one-time snapshot.snapshotHash bound to prompt, sourceNodeIds, operationsPerAsset, TaskScope, and billing. Execute only by repeating those exact values with confirmed=true and expectedSnapshotHash. Changed inputs, stale canvas state, cross-project use, and replay fail with zero dispatch. The command waits for the current Agent turn to settle.
- `commerce.compose-set`: `{"sourceNodeIds":["SOURCE_A","SOURCE_B"],"plan":{"mode":"generate","title":"Marketplace listing set","setSize":2,"slots":[{"id":"hero","title":"Hero image","prompt":"Keep the exact product identity and create a clean white-background hero composition."},{"id":"detail","title":"Detail image","prompt":"Show the real visible material and construction details without inventing specifications."}],"languageCodes":["en-US","de-DE"],"saveTarget":"requirement","reusableName":"Marketplace listing-set requirement"}}`. Compose a deterministic cross-border commerce listing-set prompt and submit it through the same two-stage Goal preview/confirmation gate. sourceNodeIds are exact and atomic. The plan determines operationsPerAsset. Preview returns confirmationArgs containing the original sourceNodeIds and plan, plus composition.normalizedPlan for observation and the compatibility alias composition.plan. Execute only by spreading confirmationArgs unchanged and adding confirmed=true plus the preview snapshot hash; never reconstruct confirmation input from either normalized-plan field. This command never bypasses agent.goal confirmation.
- `agent.steer`: `{"prompt":"prompt","taskScopeMode":"keep","sourceNodeIds":[],"referenceNodeIds":[]}`. Change the active task, independently keep, replace, append, or clear SOURCE/REFERENCE attachments, persist a re-hashed TaskScope snapshot, interrupt the current phase, and return only after acceptance. sourceMode/referenceMode override the compatible taskScopeMode shorthand. Every supplied node ID must exist; replace/merge requires a non-empty corresponding ID list and never executes a valid subset of a stale request.
- `agent.pause`: `{}`. Pause dispatch at the next runtime boundary; an accepted upstream request may still finish.
- `agent.resume`: `{}`. Resume a paused task and fail the command if the runtime does not accept the resume.
- `agent.stop`: `{}`. Stop the active task while preserving completed results. Missing active work or a failed backend cancellation is a top-level command failure, never a successful idle response.
- `agent.new-conversation`. Start a conversation without clearing canvas results.

## Images and containers

For generation, editing, variants, cutout, redraw, and layer work, select the intended sources and use `agent.chat`. The Agent preserves provenance and creates results through the same runtime as the GUI.

## Responses and errors

Successful output is JSON with `ok: true` and `result`. Failures use `ok: false` and `error`. Retry a `rendererReady: false` status briefly. Never expose endpoint authorization data.

## Renderer lifecycle

Every Agent run and pending automation command is owned by the Renderer that dispatched it. If that Renderer closes or crashes, naimage immediately rejects its pending CLI commands, aborts its run, and prevents further dispatch without affecting other Renderer owners. Provider requests already accepted upstream continue draining under Main-process admission and may still complete or incur charges. Application shutdown aborts all runs before transports are dismantled.

## Goal dispatch safety

A Goal preview issues a cryptographically random, ten-minute, one-time confirmation bound to the complete automation request (including prompt, sourceNodeIds, operationsPerAsset, or commerce plan), frozen TaskScope, billing quote, active project, conversation, and issuing surface. Re-previewing revokes that surface's older token. The first execution attempt burns the token before busy, preflight, live-scope, billing, or dispatch checks; changed inputs, stale scopes, changed costs, cross-context use, cancellation, and replay are rejected before dispatch and require a fresh preview. commerce.compose-set composes a structured plan but passes through this same gate. Goal execution uses the app's configured concurrency limit, but first serially probes 1-2 distinct SOURCE images, preferring different containers when available. Renderer windows share one Main-process Goal admission controller: queued probes take priority over new ramp waves, and admitted Goals fairly share the frozen process capacity. The app expands only after request acceptance, asset persistence, and result validation succeed; protected failures open a cross-Goal circuit. A bounded transport retry pauses every new ramp wave until the request settles, and closing a Renderer does not release its reservation until the real provider Promise drains. These safeguards stop only work that has not yet been dispatched. An upstream request already accepted by a provider may still complete and incur charges, so process-wide admission is not a cost guarantee.

## Commerce plan contract

For commerce.compose-set, languageCodes and targetLocales are mutually exclusive and every language code must come from the canonical commerce language registry. Unknown languages or supplying both fields fails before plugin composition, Goal preview, or provider dispatch. Treat composition.normalizedPlan and composition.plan as read-only quote details; preserve and spread the preview's confirmationArgs byte-for-byte when confirming.
